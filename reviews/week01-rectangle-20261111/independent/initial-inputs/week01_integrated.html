하나의 질문으로 시작합니다¶

일주일 동안의 기록과 잎 관찰이 있는 화분에서, 아직 재지 않은 높이를 어떻게 예상하고 확인할까요? 한 행의 뜻과 정보를 알 수 있는 순간부터 정합니다. 표와 배열의 관찰에서 특성을 만들고, 임의로 정한 식과 자료에서 실제로 배운 모델을 구분합니다. 그다음 다른 명세를 읽고 스스로 선택해 봅니다.

아래 자료는 모두 이해를 위해 만든 합성 자료입니다. 실제 식물의 성장 법칙이나 대회 데이터가 아닙니다. Python 변수·리스트·반복문·함수를 접한 학생을 위한 자료입니다. NumPy, pandas, Matplotlib, scikit-learn이 있는 Jupyter에서 위에서 아래로 Shift+Enter를 누르세요. 각 질문은 먼저 예상과 이유를 적고, 실행한 뒤 비교합니다.

1. 무엇을 언제 아나요?¶

일주일 동안 매일 같은 양의 빛과 물을 받았고 그 기록과 잎 관찰이 완성된 뒤, 높이를 재기 직전이라고 가정합니다. 기록과 잎 관찰은 사용할 수 있지만 일주일 뒤 높이는 아직 모릅니다. 심는 날에 예측한다면 앞으로 실제 받을 빛과 물은 아직 모릅니다. 계획과 실제 기록도 같다고 단정할 수 없습니다.

항목 한 화분에서의 뜻 이 예제의 역할
pot_id 화분을 찾는 이름 ID, 결과와 관찰을 연결
place 관찰 장소 기록·비교용
light_h 하루 빛 시간(h) 예측 직전 알 수 있는 특성
water_ml 하루 물의 양(ml), 빈칸은 기록 없음 예측 직전 알 수 있는 특성
잎 관찰 잎과 배경을 표시한 작은 합성 격자 예측 직전 알 수 있는 관찰
height_cm 일주일 뒤 잰 높이(cm) 나중에 비교할 정답

한 행은 화분 하나입니다. 높이로부터 만든 판정도 높이를 재기 전에는 입력에 넣을 수 없습니다. 여기서 pot_id는 연결용이지만 다른 문제의 ID도 항상 입력에서 빼야 한다는 규칙은 아닙니다. 그 ID가 예측 시점에 주어지고 대상의 차이를 설명할 수 있는지는 명세와 문제 목적을 보고 판단합니다.

아래 표는 기존 화분 예시를 참고하되, 새로운 비교를 위해 두 행의 일부 값을 바꾼 별도 합성 표입니다.

먼저 예상: P01의 물 0과 P03의 빈칸은 같은 뜻인가요? 높이를 예측할 때 height_cm을 입력으로 쓰면 왜 안 될까요?

2. 관측한 것만 세어 평균을 구하기¶

물 기록 중 실제 숫자는 0, 20, 40, 10, 50ml입니다. 합계 120 ÷ 관측 개수 5 = 평균 24ml입니다. 이 값은 기록된 다섯 화분의 평균이며, 빈칸을 모르는 지금 여섯 화분 전체의 실제 평균은 알 수 없습니다.

다음 함수에서 total은 합계, count는 관측 개수입니다. 정상 입력은 길이 0~10,000인 리스트이며 각 관측값은 −1,000,000~1,000,000 범위의 유한한 Python 정수·실수이고 참·거짓은 포함하지 않습니다. 결측은 None 또는 NaN입니다. pandas가 CSV 빈칸을 읽을 때도 NaN으로 표시합니다. pd.isna로 None과 NaN을 모두 제외하지만 0은 셉니다. 관측이 없으면 평균 대신 None을 반환합니다. 범위 밖 입력은 따로 검사하거나 결과를 보장하지 않습니다. 실수 계산에는 반올림 오차가 있을 수 있습니다. 화면에 출력하는 것과 나중에 쓸 값을 return으로 돌려주는 것은 다릅니다.

먼저 예상: [0, None, 6]의 관측 개수와 평균은 얼마인가요? [None]이면 무엇을 돌려줄까요?

In [3]:
def observed_mean(values):
    total = 0
    count = 0
    for value in values:
        if not pd.isna(value):
            total = total + value
            count = count + 1
    if count == 0:
        return None
    return total / count

water_records = plants["water_ml"].tolist()
water_average = observed_mean(water_records)
print("CSV의 관측 평균(ml):", water_average)
print("[0, None, NaN, 6]의 평균:", observed_mean([0, None, np.nan, 6]))
print("관측이 없는 경우:", observed_mean([None, np.nan]))
assert water_average == 24 and observed_mean([0, None, np.nan, 6]) == 3
assert observed_mean([0]) == 0 and observed_mean([]) is None

[0, None, NaN, 6]의 평균: 3.0
관측이 없는 경우: None

평균이 같아도 퍼짐은 다릅니다¶

P01~P03의 높이 [8,10,12]cm의 평균은 10cm, 평균에서 뺀 편차는 [−2,0,2]cm입니다. 편차의 합은 0이지만 값이 모두 같은 것은 아닙니다. 편차를 제곱해 더하고 개수 3으로 나눈 분산은 (4+0+4)÷3 = 8/3cm²입니다. 여기서는 주어진 세 값 전체의 퍼짐으로 보고 분모를 n으로 정합니다. 같은 평균의 [10,10,10]은 분산 0입니다. 제곱했으므로 분산 단위는 cm²입니다.

3. 표의 축과 모양 바꾸기¶

P01, P02, P04가 이틀 동안 받은 빛 시간이 매일 같았다고 놓으면 다음 표가 됩니다. 행은 화분, 열은 날이고 모든 숫자의 단위는 h입니다.

화분 첫날(h) 둘째 날(h)
P01 2 2
P02 3 3
P04 6 6

shape (3, 2)에서 axis 0은 행, axis 1은 열입니다. mean(axis=0)은 행을 모아 날마다 하나씩, mean(axis=1)은 두 날을 모아 화분마다 하나씩 냅니다. 첫날 평균은 (2+3+6)÷3 = 11/3h, P02 평균은 (3+3)÷2 = 3h입니다. 빛 h와 물 ml처럼 뜻과 단위가 다른 열끼리 한 행 평균을 내서는 안 됩니다.

reshape, 전치와 broadcasting¶

reshape는 원소 수를 유지하며 자리를 다시 나눕니다. .T는 행·열 축을 교환합니다. 둘 다 (2,3)이어도 값의 대응은 달라질 수 있습니다. 두 결과의 첫 행을 먼저 예측하세요.

(3,2) + (2,)은 각 행의 첫째 날에 1h, 둘째 날에 2h를 더합니다. 크기는 오른쪽 축부터 비교합니다. 반면 (3,2) + (3,)은 맨 오른쪽의 2와 3이 달라 맞지 않습니다.

같은 화분의 잎 관찰을 특성으로 만들기¶

이제 각 화분에 예측 직전에 얻은 작은 합성 잎 관찰을 하나씩 붙입니다. 사진 모델을 배우는 예제가 아니라 값의 뜻과 축을 읽는 연습입니다. 화분 하나의 관찰은 (2,2,2): 행, 열, 채널 순서입니다.

채널 코드의 뜻
0: 물체 0은 배경, 1은 잎
1: 색 잎이면 0은 초록, 1은 노랑. 배경의 색 코드는 의미 없음

예를 들어 P02의 [0,1]은 [잎, 노랑], [1,0]은 [잎, 초록]입니다. 코드는 종류를 표시하는 이름이므로 1이 0보다 크다는 사실만으로 잎이나 색의 크기·거리를 뜻하지 않습니다. 한 칸은 0부터 세고 관찰[행, 열, 채널]로 찾습니다.

먼저 예상: P02에서 노란 잎은 몇 칸인가요? 색 코드가 1인 모든 칸을 세면 배경도 세게 될까요? 행과 열을 바꾼 뒤에도 shape가 같다면 같은 위치의 뜻도 항상 같을까요?

한 칸이 잎 이면서 노랑일 때만 1, 그렇지 않으면 0으로 셉니다. 행을 r, 열을 c, 관찰을 G라고 하면

노란 잎 수 = Σ(r=0부터 1) Σ(c=0부터 1) [G[r,c,0]=1 이고 G[r,c,1]=1]

대괄호의 조건이 참이면 1, 거짓이면 0입니다. P02의 네 칸을 차례로 확인하면 0+1+0+0=1입니다. 다음 함수는 한 화분의 유효한 (2,2,2) 관찰을 받아 정수 개수를 돌려줍니다. 물체와 색 코드를 각각 비교한 뒤 &로 두 조건을 합칩니다. 배경 색만 바뀌어도 답은 그대로여야 합니다.

ID는 이미지를 화분에 연결하는 데 씁니다. 표 행의 순서로 ID를 찾아 각각의 개수를 만들므로, 표만 정렬해도 다른 화분의 이미지가 섞이지 않습니다. 숫자 코드끼리 평균을 내는 대신, 이처럼 명세에 맞는 의미 있는 양을 만듭니다.

def count_yellow_leaf(image):
    objects = image[:, :, 0]
    colors = image[:, :, 1]
    return int(((objects == 1) & (colors == 1)).sum())

print("P02 색 1인 모든 칸:", int((p02_image[:, :, 1] == 1).sum()))
print("P02 노란 잎 수:", count_yellow_leaf(p02_image))
background_changed = p02_image.copy()
background = background_changed[:, :, 0] == 0
background_changed[:, :, 1][background] = 1 - background_changed[:, :, 1][background]
print("배경 색만 바꾼 뒤:", count_yellow_leaf(background_changed))

yellow_by_id = {pot: count_yellow_leaf(image) for pot, image in leaf_images.items()}
print("각 ID의 노란 잎 수:", yellow_by_id)

assert count_yellow_leaf(background_changed) == 1
assert [yellow_by_id[pot] for pot in plants["pot_id"]] == [0, 1, 2, 3, 2, 3]

격자의 한 영역을 정확히 남기기¶

앞에서 P02의 잎 관찰 전체를 살폈습니다. 이번에는 원래 격자의 지정된 위치만 남기는 다른 합성 연습을 합니다. 다음 작은 표는 행 8, 열 12인 (8,12) 배열이며 값은 위치를 구별하기 위한 숫자입니다. 실제 사진이나 대회 데이터는 아닙니다.

사각형의 왼쪽 위 경계가 (top, left), 오른쪽 아래 경계가 (bottom, right)라고 약속합니다. 순서는 행, 열입니다. 시작은 포함하고 끝은 포함하지 않으므로, 남기는 칸은 top ≤ 행 < bottom, left ≤ 열 < right입니다. 높이 H와 너비 W에서 비어 있지 않은 사각형을 이 연습에서는 이렇게 정합니다.

$$0 \leq top < bottom \leq H,\quad 0 \leq left < right \leq W,$$ $$\text{칸 수}=(bottom-top)\times(right-left).$$

((2,4),(4,7))이면 행 2·3과 열 4·5·6, 모두 2×3=6칸입니다. 아래 합성 계약의 한도도 6칸이므로 정확히 한도에 맞습니다. 전체 96칸 중 6칸은 1/16입니다. 먼저 배열과 마스크의 모양, 선택되는 두 행 세 열을 적어 보세요.

**잘라낸 부분(crop)**은 (2,3)이지만, 위치를 표시하는 마스크는 원래 공간 전체인 (8,12)입니다. 마스크의 참은 남길 칸이고, 거짓은 나머지 칸입니다. 원본 크기 결과는 선택 칸의 원래 값을 복사하고 밖을 0으로 둡니다. 원래 값이 0이어도 선택된 칸이면 면적에 포함하므로, 결과의 0이 아닌 값 개수만 세어 면적을 정할 수 없습니다. 원본은 그대로 둡니다.

좌표의 끝이 H나 W와 같은 것은 허용되지만, 끝이 H나 W를 넘거나 시작 이상으로 끝나지 않는 영역은 이 계약에서 오류입니다. NumPy는 어떤 범위 밖 슬라이스를 오류 없이 잘라 내므로, 자르기 전에 범위와 면적을 확인합니다. RGB처럼 채널이 여러 개여도 공간 칸 수는 행×열로 셉니다. 여기서는 2차원 배열만 구현합니다.

이 연습은 IOAI 2025 Pixel Efficiency 원문의 공간 경계를 작게 옮긴 것입니다. 공식 문제는 (224,224) 이미지에서 최대 6.25%를 남길 좌표를 고르고 분류 정확도를 평가합니다. 실제 제출은 이미지 ID와 좌표의 JSONL이며, 여기의 전체 마스크는 좌표를 확인하는 중간 결과입니다. 좌표가 유효해도 분류에 유용한 영역인지는 별도 질문입니다. 이 합성 계산이 국제 문제를 푼 것은 아닙니다.

5. 정한 식과 배운 모델은 다릅니다¶

먼저 고정식을 계산하기¶

높이 예측을 설명하려고 임의로 다음 식을 정해 봅니다.

예측 높이(cm) = 4 + 1 × 빛 시간(h) + 0.1 × 물(ml)

1의 단위는 cm/h, 0.1의 단위는 cm/ml이므로 각 항은 cm입니다. P02에 넣으면 4+3+2=9cm입니다. 나중에 잰 높이는 10cm이므로 실제 − 예측 = +1cm입니다. 이 계수는 자료로 학습한 값도 실제 효과도 아닙니다. P03의 물은 미상이므로 빈칸을 어떤 값이라고 약속하지 않고서는 이 식을 바로 계산할 수 없습니다.

빛과 물을 순서대로 벡터 [3,20], 계수를 [1,0.1]로 놓으면 짝별 곱의 합이 내적입니다. 순서가 바뀌면 길이가 같아도 다른 계산이 됩니다.

이제 질문을 바꾸어 작은 분류 모델을 학습하기¶

이번에는 높이 자체가 아니라 높이가 12cm 이상인지를 예측합니다. 나중에 잰 높이로 만든 0/1이 정답입니다. 이 두 질문의 출력 뜻과 단위가 다릅니다. P01~P04는 훈련, P05~P06은 별도 검증으로 정합니다. 서로 다른 화분이라고 가정합니다.

이 예의 입력으로 물의 양과 방금 만든 노란 잎 수를 고릅니다. 빛도 사용할 수 있지만 이번 모델에서는 쓰지 않습니다. 나중 높이·그 높이에서 만든 정답·연결용 ID는 모델 입력에 넣지 않습니다. 우선 훈련의 물 [0,20,결측,40] 중 관측한 값으로 평균 (0+20+40)÷3 = 20ml를 배워 빈칸을 채웁니다. 전체 기록의 평균 24ml를 쓰면 검증 정보가 섞입니다.

물을 미리 정한 10ml 단위로 나타내면 20ml는 숫자 2입니다. 이것은 이 예에서 정한 기준이지 자료를 보고 찾은 최적값이 아닙니다. 두 입력은 순서대로 [물/10ml, 노란 잎 수]입니다. 각 행의 ID로 관찰을 찾아야 물과 잎 수가 같은 화분의 값이 됩니다.

평균은 왜 중심이 될까요?¶

정답이 0인 훈련 화분의 물은 0ml와 20ml입니다. 대표값 후보를 0·10·20ml로 놓으면, 각 값에서 후보를 뺀 뒤 제곱해 더한 값은 각각 400·200·400ml²입니다. 평균 10ml에서 가장 작습니다. 실제로 후보를 m이라 할 때

(0−m)² + (20−m)² = 2(m−10)² + 200

제곱은 0 이상이므로 10ml가 이 합을 가장 작게 합니다. 두 값의 분산은 가장 작은 합 200을 개수 2로 나눈 100ml²입니다. 이 성질 때문에 각 정답별 특성의 평균을 중심으로 쓰는 방법을 살펴봅니다. 이것이 모든 분류기의 최선이라는 뜻은 아닙니다.

각 정답 c와 입력 열 j에 대해 중심 μ(c,j)는 그 정답인 훈련 행들의 j열 합 ÷ 그 행의 개수입니다. 방금 만든 X에서 0의 중심은 [1, 0.5], 1의 중심은 [3, 2.5]입니다. 예를 들어 0의 첫 좌표는 (0+2)÷2=1입니다.

새 입력 x와 중심 μ의 제곱거리는 각 열의 차이를 제곱해 더한 Σ(j=1부터 2) (x(j)−μ(c,j))²입니다. 두 값이 음수가 아니므로 제곱근을 계산하지 않아도 어느 쪽이 가까운지 비교할 수 있습니다. 물/10ml와 잎 수를 같은 한 좌표씩 비교하는 선택은 두 특성의 상대적 영향에 영향을 줍니다. 기준을 다르게 정하면 예측이 달라질 수 있습니다. 다음은 여러 가능한 분류기 중 하나입니다.

훈련에서 배운 20ml 대체값을 검증에 그대로 적용하고, 같은 ID의 잎 관찰을 찾고, 같은 열 순서와 10ml 기준을 사용합니다. P05는 물 10ml·노란 잎 2개이므로 입력은 [1,2]입니다.
