# 1주 독립 문제 검토

기준은 기존 lesson 브랜치 `e3d3afdee8d2ad60141ca7a91b5b5bf3e7d3ec6d`와 해당 체크아웃의 동결된 후보이다. 최종 통합 노트북 SHA-256은 `88d169a244b1f4c0caeb885bb0bd1627cacf74aa6eaebe6dbb69d3ea8f94adb2`, 통합 교사용 `fe584d8ccdd7e51169b3ab852c0bef8388f3d1ce7a5374615428d30dda3fc40b`, 검증 정답 CSV `eeda4512bdc920d3101c65fb8d594c9bc074c810bfea1d48f854ea3a8be3b6a6`이다. [검토 기준](criteria.md)은 최종 수정본의 해시가 정해지기 전에 작성했다. 이전 통합 후보 파일을 복원한 것이 아니며 접근할 수 없는 사용자 작업 전체의 보존을 입증하지 않는다.

## 우선순위와 원문

[KOAI 2027](https://kitpa.org/koai/2027)은 중등부의 1~4과목 필기와 코딩을 안내하며, 연결된 [출제 기준](https://kitpa.org/koai/syllabus)은 확인 당시 IOAI 2026 기준으로 표기되어 있다. [IOAI 2025 Antique](https://raw.githubusercontent.com/IOAI-official/IOAI-2025/main/Individual-Contest/Antique/Antique.ipynb)는 미상 라벨과 별도 평가·제출을, [IOAI 2026 Robot Chasing](https://raw.githubusercontent.com/IOAI-official/IOAI-2026/e1963801aa4cf33a5a03520b39fa6620a7894c54/Individual-Contest/2_Robot_Chasing/statement.md)은 위치와 채널, ID, 별도 지시와 새 조합을 읽는 능력을 요구한다. 두 국제 개인전 문제는 선수 역량 비교 자료이며 국내 중등 기출이나 아래 축소 예제의 해결 결과가 아니다.

기존 1주 통합 경로는 이미 고정식과 학습 모델, 훈련 전용 결측값 대체·검증, 결과 ID, 화분 관찰을 다룬다. 축·ID 교량에는 행렬곱·토큰 조회·유효 위치 평균과 검색이 있고, 본문에는 Python 함수·표·평균·분산·새 입력 문제가 있다. 새로운 주제를 덧붙이기보다, 기존 기기 독립 문제에서 데이터가 서로 바뀌지 않고 첫 선택→검증→새 입력 결과로 이어지는지 고치는 것이 먼저라고 판단했다. 이는 2주의 전처리·평가와 뒤 주차의 모델·표현 학습을 위한 연결이지, 10주 범위의 완수나 충분한 이론 깊이의 증거가 아니다.

## 실제 전후 기능 확인

- 원본의 실제 입력 셀에서 훈련 T2의 한 칸을 바꾸자 새 기기 N7도 `[1,2]→[0,2]`로 변했고, T4·V4·N3도 같은 객체를 공유했다. 후보에서는 기존 숫자와 ID를 보존하면서 11개 행의 55쌍이 메모리를 공유하지 않았다. 매 행을 하나씩 바꿨을 때 나머지 10행은 유지됐다.
- 후보에서도 `DataFrame.copy(deep=True)`만으로는 셀 속 ndarray를 별도 복사하지 않는다. 표 복사 후 각 `panel`을 `.copy()`하면 실험용 배열을 바꿔도 원본은 유지됐다. 이는 [pandas 문서](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.copy.html)의 객체 재귀 복사 경계와 맞는다. 배열 참조를 분리한 것이 관측의 통계적 독립성을 입증하지는 않는다.
- 후보의 검증 입력에는 정답 열이 없고, V9 정상·V4 점검·V7 점검은 첫 예측 뒤 확인하는 별도 CSV에 ID별로 보존됐다. 자습 경로와 정답 파일이 공개되어 기술적 접근 통제가 아니라는 사실, 검증 선택과 제공되지 않는 최종 테스트의 차이가 명시됐다. 이는 실제 학생이 정답을 보지 않았다는 증거가 아니다.
- 검토자만 별도 코드로 실제 중심 분류기와 깊이 2 결정 트리를 학습했다. V9/V4/V7 순서 예측은 각각 정상·점검·정상과 정상·점검·점검이었고, 새로운 기기의 결과는 요구된 N7/N3/N1 순서로 연결됐다. 세 행에서 나온 정확도는 학생의 점수나 일반화 성능이 아니다. 검증 정답 행의 순서를 거꾸로 하여도 ID로 대조되는 것을 확인했다. 검토자가 별도로 작성한 기준 구현은 정상·순서 변경은 허용하고 정답과 예측의 ID 누락·중복·추가와 유효하지 않은 값 8종, 제출의 순서·누락·중복·유효값 오류 4종을 거절했다. 학생용 자동 채점기나 학생이 작성한 코드의 시험이 아니다.
- 교안의 실제 잎 개수 함수를 새로운 유효 `(2,3,2)` 입력, 배경만 변경, 행·열 전치, 모두 배경인 경우에 적용해 각각 기대한 수와 원본 불변을 확인했다. 학생에게 작성하도록 비워 둔 기기 첫 답안, 정답 확인 후 답안, 영역 함수 답안의 소스는 주석뿐이고 출력이 없다.

[기능 재현 코드](device_probe.py)는 저장소 루트와 동결된 SHA-256을 인자로 받으며 [실행 결과](device-results-final-v2.json)와 일치한다. 모델·특성 선택과 데이터 변형 코드는 검토자의 참조 코드다. 학생 작성 검증기나 자동 채점기가 존재한다는 뜻이 아니다.

```sh
python3 -B reviews/week01-device-contract-20261112/device_probe.py --root . --candidate-sha 88d169a244b1f4c0caeb885bb0bd1627cacf74aa6eaebe6dbb69d3ea8f94adb2 --teacher-sha fe584d8ccdd7e51169b3ab852c0bef8388f3d1ce7a5374615428d30dda3fc40b --labels-sha eeda4512bdc920d3101c65fb8d594c9bc074c810bfea1d48f854ea3a8be3b6a6
```

스크립트 파일의 경로는 실행 위치에 맞게 지정한다. NumPy·pandas·scikit-learn이 필요하다. 당시 baseline commit 객체도 Git 기록에 있어야 한다.

## 별도 커널의 학습 경로

세 개의 별도 프로세스에서 각각 in-process IPython 커널을 유지하며 통합본의 시작·기기 입력 → 본문의 안내된 준비 셀 ID `d2be9ce3`, `eb304b96`, `5c37fc90` → 통합본의 영역 입력 재생성 → 축·ID 교량 준비 함수와 독립 입력 → 통합본 복귀를 실행했다. 본문의 표는 `sunlight_hours`, 통합본의 표는 `light_h`를 사용하고 두 커널의 변수는 자동 공유되지 않았다. 본문 커널에 넣은 T와 식별자는 격리를 확인하기 위한 **검토자 fixture**이며 학생 빈 답안을 실행하지 않았다. 통합본은 실제 제공된 `rectangle-independent-input` 셀로 T를 다시 만들었다. 교량의 실제 함수에는 유효한 영벡터 토큰, 전부 PAD, 음수·범위 초과·bool ID, 영벡터와 NaN도 시험했다. [경로 재현 코드](route_probe.py), [경로 결과](route-results.json). 이 선택 셀 경로 검사는 전체 코드를 표준 Jupyter 서버에서 실행하거나 학생이 직접 해결한 증거가 아니다.

## 보존과 한계

기존 통합본 44셀의 ID와 순서가 유지됐고 새 단계 셀 두 개 외에 지정된 네 셀만 소스가 바뀌었다. 나머지 셀의 소스·첨부는 그대로다. 본문 노트북, 본문 교사용, 축·ID 교량과 그 교사용의 바이트는 기준 커밋과 같으며, 검사 시점에 2주차와 10주 계획의 로컬 변경은 없었다. 통합 교사용 해설에는 현재 96셀 본문과 과거 89셀 기준을 구분했다.

통합 문제 외에도 본문 필수 A–E와 교량 필수 A/B가 남는다. 현재 범위의 실제 중학생 수행 시간, 필요한 도움과 낯선 문제로의 전이는 관찰하지 못했다. 자동 실행·참조 모델로 학습 가능 시간, 독립 수행 또는 성취를 판정하지 않는다. 일반 Jupyter/Colab과 HTML 전체의 브라우저 표시 확인은 이 독립 기능 검사에 포함되지 않는다.

별도 관찰로, 기준 커밋의 본문 교사용 `teacher-notes.txt`는 `validate_week01.py`와 `validation.json`이 동봉되지 않았다고 적지만 두 파일은 같은 폴더에 존재한다. 이번 독립 검토에서 해당 사용자 파일을 수정하지 않았다. 과거 검토 기록과 예전 검증기의 오라클은 그 기록이 대상으로 삼은 당시 교안에 묶인 이력이므로 덮어쓰지 않았다.
