## 실행 결과와 검출 주체

본문25셀/코드8셀, 보충25셀/코드10셀을 각각 새 subprocess/fresh in-process 커널에서 모두 실행했다. 저장 텍스트·출력 종류·PNG 존재의 대조가 통과했다. 학생 빈칸까지 실행된 것이며 학생 해답을 완성한 것은 아니다. 보충 전체 실행 뒤 실제 `fit_known_mode`와 반환된 모델·기존 native 지표 함수에 동결 입력을 적용한 독립 oracle도 통과했다.

실제 helper에 검증 라벨을 훈련 인자로 붙인 잘못된 호출은 다른 기준을 반환했다. 이 함수는 인자의 출처를 알 수 없으므로 **train-only를 자동 강제하는 함수는 아니다**. 검토자 oracle이 미리 정한 올바른 기준과 비교해 경계 위반을 검출했다. 검증 결과로 목적에 맞는 후보를 선택하는 역할과 검증 라벨로 기준을 재fit하는 오류는 구별한다.

후보가 상수 예측만 내므로 예측 배열만으로 ID 순서 오류를 찾았다고 하지 않았다. 별도 비상수 동료 후보의 검토자 prediction ledger에서 ID 재배열·역순 오류를 대조했다. 이 ledger는 실제 학습된 모델이 아니다. 별도 DummyClassifier에 두 frozen X를 fit한 검사는 해당 알고리즘의 특징값 독립성 확인이며 helper에 X 매개변수가 있다는 뜻이 아니다.

## 변이와 별도 분할 참조

실제 보충16 코드에서 Boolean 방어만 제거한 변이는 False를 받아들였고, 검토자 oracle의 예상 ValueError 검사에서 정확한 AssertionError로 검출됐다. raw status는 `oracle_error`이다. 교안 원본의 정상 실패나 교안 자체의 자동 채점기로 오해하지 않는다.

다른 ‘unknown을 known_mask에 포함’ 시도는 raw 결과가 **passed**였다. 혼합 리스트가 문자열 비교값으로 변해 수치0에 의도한 의미 변화가 없었던 무효한 변이로 판정했다. 이를 검출 성공으로 세지 않는다. 최초 의도·실제 결과·이유·원시 config는 `mutation-assessment.json`에 보존했고 부모의 종료 지시 후 대체 시험을 추가하지 않았다. 원본 함수의 미상 제외 정상 검사는 별도로 통과했다.

실제 학생 교안에는 범용 분할 판정 함수가 없다. 별도 검토자 참조는 같은 ID의 친숙한 요소/새 조합이라는 명시적 합성 계약에서 두 유효 분할을 수용했고, 조합 누출·없는 과거 사용·다른 목표의 새 ID 분할을 각각 예상 ValueError로 거부했다. 새 ID 목표로 계약을 바꾸면 그 분할을 수용했다. 참조의 전역 조합 보류 조건은 검토자가 별도로 명시한 조건이며 학생의 간단한 선택 문항이 그 코드를 구현했다는 증거가 아니다. 공식 Robot 데이터의 실제 분할·모델을 재현하지 않았다.

## 내용·기존 목표·부담

본문12와 보충14/16은 사람이 지정한 constant−1, 훈련 라벨 최빈 기준, X–y 관계를 배우는 비상수 모델을 구별한다. 알려진 훈련 N행에서 상수 c의 정확도 n_c/N이라는 원리와 동률 중단 정책이 명확하다. 동결 참조의 -1 동률 선택과 실제 교안의 동률 중단은 다른 명시적 정책이다. 사전 기준은 유일한 반환 클래스를 강요하지 않았다.

기존 B5/T1 표를 재사용해 높은 정확도와 양성 재현율0, 정밀도 정의 불가, F1·가중 목적을 연결한다. 독립 문제의 T 기준/U/V 교사용 계산도 일치한다. 정확도는 U, 재현율은 T 기준과 V 공동, 가중 점수는 V가 높다는 구분이 있다. 어느 지표나 다수 기준이 언제나 최적이라고 하지 않는다. 기존 AUC·전처리·새개체/미래·선택고정·최종 테스트 보류·4주 연결을 보존했으며 이전 모든 제공 코드의 source를 ID별로 대조해 유지됨을 확인했다.

보충17의 합성 (가)는 알려진 로봇의 새 조합, (나)는 새 로봇을 평가한다. [Robot Chasing 원문](https://raw.githubusercontent.com/IOAI-official/IOAI-2026/main/Individual-Contest/2_Robot_Chasing/statement.md)의 동일 여섯 로봇·독립 snapshot·이전 기록 미제공과 구별하며 어느 합성 분할도 공식 실제 분할이라고 하지 않는다. [DummyClassifier 문서](https://scikit-learn.org/stable/modules/generated/sklearn.dummy.DummyClassifier.html)의 X를 무시하고 훈련 y에서 정하는 동작과도 일치한다.

기존6번을 확장해 새 대형 문제 번호를 늘리지는 않았지만 코드 셀1개와 여러 필수 수행 단계가 증가했다. 교사용 문서가 이를 명시한다. 학습량이 줄었다거나 기존120분/자습 안에 끝난다고 판단하지 않는다. dtype=object·타입 방어 등 지원 코드의 읽기 부담은 남으며, 실제 이해·도움·시간은 관찰되지 않았다. 학생 본문20/보충23은 주석만 있고 답안 출력이 없다. 공개 저장소의 교사용 해설·검토 입력은 접근통제된 시험이 아니다.

## 재현·미실행

`execute_notebook_case.py`와 `case-configs/`는 independent 기준 상대경로를 쓴다. 준비된 Python에서 설정 사본의 id를 새 값으로 주고 실행하면 기존 runs를 보존할 수 있다. 원본 입력 SHA를 검사한다. 실제 다른 checkout의 재배치 실행, 전체 브라우저/MathJax 시각 검증, 새 CLI·생성기 검사, 새 학생 해답·성취·실측시간·접근통제된 최종 테스트는 수행하지 않았다. helper에 없는 imputer의 frozen X 평균을 새로 fit 검증한 것도 아니며, 기존 제공 전처리 assert만 전체 실행에서 확인했다. 작성자의271개 회귀를 본 독립 결과에 합산하지 않았다.

모든4회 커널 실행에서 원본 snapshot은 불변이며 runtime/cache는 제거됐다. 정상·예상 오류·무효 변이·고정 입력·스크립트·원시 traceback을 보존했다. 1주/사용자 작업/학생·교사용 원본/index/remote는 변경하지 않았다. 현재 유한 검토 범위에서 추가 수정필수 교안 결함은 재현하지 못했다.
