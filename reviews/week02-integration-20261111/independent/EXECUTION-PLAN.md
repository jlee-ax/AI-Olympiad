# 후보 수령 후 독립 실행 계획 · 아직 미실행

최종 후보 SHA와 부모의 검토 지시 전에는 후보 변경을 열거나 실행하지 않는다. 현재 고정 입력과 기준을 결과에 유리하게 바꾸지 않는다. 최초 baseline·원래 freeze·추기 원문도 보존한다.

1. 두 학생 notebook/HTML/teacher, validator와 builder의 실제 변경을 직접 읽고 SHA snapshot을 새 independent 안에 보존한다. worked subset, 확장 훈련 코호트, 각 CV fold의 입력·fit 상태를 각각 식별한다. 수식/표/teacher 기대와 학생 빈칸을 구분한다.
2. 실제 제공 셀 전체와 연결 경로를 새 subprocess/fresh in-process kernel에서 실행한다. 새 입력을 처리하는 실제 helper가 있으면 직접 호출하고 없으면 검토자 참조 풀이로 분리해 기록한다. 학생 답안이 비어 있는 사실과 실제 성취를 혼동하지 않는다.
3. 복수 타당 분할은 정확한 ID partition 하나 대신 그룹·행 무중복/허용 시점·훈련 클래스·fit 가능성으로 검사한다. 원래 worked 두 그룹의 단일클래스 fold는 iterator 오류가 아닌 두클래스 학습 계약의 불가능 대조다. 새 확장/각 fold에서 실제 전처리 상태를 독립 합계·관측수·분산과 비교하며 전체 코호트 통계 재사용을 감지한다.
4. 별도 목적의 시간/그룹 규약을 적용하고, 적법한 과거 문맥과 학습형 fit의 경계를 나눈다. 동일 검증에서 명세의 공식 지표로 선택한 뒤 고정하고 새 무라벨 입력에 그대로 적용하는 경로를 확인한다. 동률/미상·분모와 목적이 다른 지표의 반전은 사전 입력 기대와 비교한다. 제공 점수를 실제 학습 모델로 부르지 않는다.
5. 기존/수정 검증기와 builder는 원본 lessons 경로에서 실행하지 않는다. 한 케이스마다 별도 복제본·새 출력 경로·runtime을 만들고 원본/보호 sentinel의 바이트 SHA를 전후 비교한다. 기본 성공·의도적 코드/입력 실패·학생답안 AST guard·출력충돌·명시적 재생성을 검사한다. 실패 후 이전 성공결과를 현재 성공으로 재사용하지 않는다. 원래 재생성의 학생 source/ID/빈칸·임시 QA 제거·실행 출력/HTML/report 기능도 확인한다.
6. 각 오류 변이는 정상 control 후 한 부분씩만 적용한다. raw stdout/stderr/traceback과 기대·실제·검출주체를 남기고, 임의 실행기 오류를 의미 오류 검출로 세지 않는다. 검토기 실패는 원래 결과를 보존하고 새 수정판으로 재검사한다. 새 checkout 대표 경로는 명시적 root rebasing과 새 output ID로 확인한다.
7. 도구/소스/이력·사용자 자료의 보존과 임시 cache 정리를 확인하고, 자동검사 구조·자료 설계 판단·학생 성취를 분리해 보고한다. 일반 커널 소켓·browser 정책을 우회하지 않는다. 1주 파일/사용자 작업/무관 스레드를 건드리지 않는다.

새 fixture/교안/검사기를 아직 실행하지 않았다. 구체 입력은 저자·다른 agent 작업 설명에 공유하지 않으며 공개 저장소가 접근 차단된 시험이라고 주장하지 않는다.
