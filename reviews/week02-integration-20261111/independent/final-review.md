# 2주 독립 검토 최종 기록

대상은 본문 `7bfe0429…`, 보충 `b5f555d8…`이다. 정확한 8개 artifact SHA와 원시 결과 SHA는 `final-results.json`에 있다. 현재 파일과 전달된 SHA가 모두 일치했다. 1주 파일·사용자 작업·index·원격은 다루지 않았다.

## 실행 판정

| 검사 | 기대 | 실제와 범위 |
|---|---|---|
| main-full | 제공 코드 전부 실행, 저장 텍스트와 일치 | 통과. 25셀 중 코드 8셀(빈 학생 셀 포함), 새 subprocess/fresh in-process 커널 |
| temporal-full | 제공 코드 전부 실행, 저장 텍스트·PNG 존재 대조 | 통과. 24셀 중 코드 9셀(빈 학생 셀 포함). PNG는 존재·형식 대조이며 픽셀 동일성을 주장하지 않음 |
| core-cv | 유효한 복수 분할 수용, fold 훈련 전용 fit, 잘못된 그룹/단일클래스/누수 거부 | 통과. 후보의 실제 확장 자료를 5개 분류기 계열로 fold별 fit/predict. 별도 고정 입력의 두 분할 계열에서 수작업 평균·분산과 fitted 상태 대조. 검증값을 바꿔도 fit 상태 불변 |
| core-decision | 지표별 선택 반전, 미상 제외, 동률 정책 고정 후 새 무라벨 적용 | 통과. 실제 `counts_at/rates/weighted_accuracy/make_features`에 독립 입력 적용. 새 과제의 별도 검토자 풀이도 통과하고 적용 중 fit 상태 불변 |

잘못된 그룹 중복, 단일클래스 훈련 fold(두 방향), fold 밖을 포함한 전처리 fit, 다른 지표로 선택, 최대화 대신 최소화는 예상한 조건으로 검토자 oracle이 검출했다. 원시 traceback은 각 `runs/core-*/result.json`에 보존했다. 이는 교안에 학생 해답의 자동 검출기가 있다는 뜻이 아니다. `>=`를 `>`로 바꾸는 경계, 미상 0을 음성으로 합치는 정책, 같은 검증 점수의 두 임계값이 새 입력에서 다른 예측을 내는 반례도 확인했다. 후보를 수정한 광범위 변이시험으로 세지 않는다.

## 동결 기준별 내용 판정

**A — 유한 사례에서 충족.** 본문 셀4/5는 A/B worked subset을 유지하면서 G/H 확장 후보를 구분한다. A/B의 기존 통계·누수 예시 9가 유지되고, 4주 조건으로 다시 fit한 전체 표본 수는 8이다. 평균과 분산이 우연히 기존 값과 같으므로 숫자 일치만으로 재fit을 판단하지 않았다. 교사용 한 분할을 유일한 정답으로 강요하지 않고 두 개의 독립적인 유효 분할 계열을 실행했다. 같은 개체의 미래라는 다른 계약에서는 그룹이 겹쳐도 허용할 수 있음을 별도로 수용했다. 이는 4주 전체 구현·성능 추정 검증은 아니다.

**B — 내용·유한 계산에서 충족, 학습자 수행은 미관찰.** 본문 셀22는 보충과 같은 필수 활동을 중복 제출하지 않도록 연결하고, 측정 직후와 측정 전의 사용 가능 정보 차이를 보존한다. 보충 셀16–21은 분할 근거→train-only 변환→같은 검증 자료에서 F1 비교→동률 해소→선택 고정→새 무라벨 적용을 요구한다. 실제 helper를 호출했으나 CV 절차와 새 문제 해답 코드는 검토자 작성 참조이다. 본문20/보충22는 빈 답안이므로 학생이 독립적으로 해결했다고 세지 않았다. 보충의 특정 시점·전체 행 제약은 허용 분할을 좁히며, 이를 모든 목적에 보편적인 분할로 일반화하지 않는다.

**C — 정적 검토만 부분 충족, 독립 CLI 실행 미검증.** 본문 validator `bcb7c3be…`는 기본 메모리 검사, 명시적 새 출력 디렉터리, 기존/심링크 경로 거부, 소유 출력의 실패 정리와 원본 변경 탐지를 구현한다. builder `45763bd5…`에는 main guard·새 경로 exclusive 생성이 있다. 하지만 본 독립 검토에서 이 CLI의 정상/오류 대표 경로는 실제 실행하지 않았다. 하위 검토자도 SHA 확인과 정적 읽기만 완료했다고 보고했다. 작성자 회귀 33건·추가 검사와 본 독립 실행을 합쳐 부풀리지 않는다. 최신 보충 validator `60fb7985…` 역시 기능 미검증이다.

## 발견·보존·한계

첫 실행 후보 `909e3cd0…`의 보충19가 앞의 독립 문제에서 요구한 범위 계산값을 숫자로 노출하는 문제를 기록했다. 최종 `b5f555d8…`에서는 해당 단서를 제거했다. 후보01/02 원바이트·첫 판정·고정 v2 입력은 보존했으며, 두 후보 사이 변경은 해당 Markdown뿐이고 코드/저장 출력은 같다. 최신 교사용 문서(`final-teacher-notes.md`, `final-week02_temporal_preprocessing_teacher.md`)는 본문 검사기의 범위와 별도 CV 검산, 보충 검사기와 학생 새 과제의 차이를 명시한다. 현재 시험 범위에서 추가 수정필수 결함은 재현하지 않았다.

전처리·지표·과거 창·범주·시점의 기존 수학을 삭제할 근거는 없다. 새로운 선택 과제와 4주 코호트 구분이 추가되므로 전체 부담이 줄었다거나 적정 시간 안에 끝난다고 판단하지 않는다. 실제 학생 이해·도움·수행·시간, 3–10주 전이 성취, 접근이 차단된 진짜 최종 테스트는 미관찰이다. 완성 예와 검토자 풀이의 실행은 이를 증명하지 않는다. 공개 저장소의 독립 입력도 접근 통제된 시험이 아니다.

네 실행의 입력 SHA가 유지됐고 각 runtime은 제거됐다. 최종 점검에서 runtime/캐시 디렉터리는 남지 않았다. PNG·원시 출력·예상 오류 traceback·고정 입력·검증 코드는 유지했다. 일반 소켓 커널/브라우저 정책을 우회하지 않았고 전체 HTML/MathJax 시각 렌더를 검증하지 않았다.

재현은 해당 의존성을 갖춘 Python으로 각 `execute_notebook_case.py case-configs/<name>.json`을 새 subprocess에서 실행한다. 기존 `runs/<id>`를 덮어쓰지 않도록 설정 사본에서 새 id를 사용한다. 현재 설정의 notebook/oracle 절대경로는 다른 checkout의 실제 independent 경로로 바꿔야 한다. 고정 입력·snapshot SHA는 그대로 검증하고, 원본 설정·원시 로그는 변경하지 않는다. 이 재배치 절차를 실제 다른 checkout에서 실행한 증거는 이번 범위에 없다.
