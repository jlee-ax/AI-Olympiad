# 선택적 재검토 표시 작업

사용자는 현재 하네스의 실제 결함을 재현한 뒤 계획·교안·근거 변경의 영향을 받는 검토를 명시적으로 재검토 대상으로 표시하고, 변경·무관한 변경·이력 보존·실패 경로를 기능 테스트하도록 지시했다. 완료 후 교안 수정은 시작하지 않는다.

기준 입력은 local `76b680d64548af5c87d0455008b25358af06a698`(원격 lesson `d59138309c63e05874203e52038533e3d91cd19f`와 동일 tree `7904d104ba18e4a645b212c3d48e11375871f057`)이다. 작업은 `codex/selective-review-invalidation-20261111`의 별도 worktree에서 진행한다. tools/tests와 필요한 하네스 문서·템플릿, 이 새 검토 폴더만 변경한다. 기존 lessons/curriculum/reviews와 사용자의 별도 미커밋 작업은 보존한다.

검증할 가설은, 누락된 입력 바인딩과 실제 변경을 구분하고 선언한 관련 영역의 현재 상태를 비교하면 전면 내용 재검토 없이도 낡은 판단 재사용을 차단할 수 있다는 것이다. 해시는 변경을 감지하는 수단이며 변경의 의미·정답·승인·학생 성취를 판정하지 않는다. 바인딩/영향 확인이 필요한 경우와 실제 내용 재검토가 필요한 경우를 분리한다.

완료 조건은 실제 옛 기록 복제본의 실패 재현, 영향받는 검토의 명시적 표시, 무관한 영역의 결과 유지, 최신 실패 우선·이력 불변, 선언 누락·파일 누락 등 실패 사례 검증, 실제 CLI/연동 확인, 독립 코드 검토 및 전체 회귀 검사다. 새 승인·합의나 스케줄을 생성하지 않는다.
