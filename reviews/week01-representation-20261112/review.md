# 1주 자료 표현 연결 독립 검토

검토 기준은 승인됐으나 원격 브랜치에 아직 연결되지 않은 직전 통합 후보의 로컬 재구성 `eb154346cfbc2f182f51a17e8b84a319f972dafb`이다. 최종 통합 노트북 SHA-256은 `527848e74da7b6c004c845d4dbe240ac54e2be46087d8e4cf3e597042b5ff181`, 통합 교사용은 `f69e6a74f7a4f1dd56400dbfdb92d0b34753238908b0c46c319ea944e8d89084`다. [사전 기준](criteria.md)은 수정본 동결 전에 정했다.

## 선택 이유와 범위

기존 통합 완성 예제는 잎 관찰을 `leaf_images[pot]` 사전으로 찾지만, 독립 기기 문제는 관찰 배열이 DataFrame `panel` 열의 각 칸에 있다. 실제 기존 입력에서 이 열은 shape `(5,)`의 object Series이고 한 칸은 `(2,2,2)` 배열이다. 열 전체를 `[:, :, 0]`으로 바로 읽으면 오류가 난다. Python 반복문의 선수 경험이 요구되므로 이 차이가 실제 학생의 실패를 입증하지는 않지만, 완성 예와 독립 문제 사이의 명시되지 않은 자료 표현 전환이다.

[KOAI 2027](https://kitpa.org/koai/2027)의 중등부는 필기와 코딩을 함께 요구하며, 연결된 [출제 기준](https://kitpa.org/koai/syllabus)은 확인 당시 IOAI 2026 기준을 표기한다. [IOAI 2025 Antique](https://raw.githubusercontent.com/IOAI-official/IOAI-2025/main/Individual-Contest/Antique/Antique.ipynb)는 특성·미상 라벨·평가 및 제출의 관계를, [IOAI 2026 Robot Chasing](https://raw.githubusercontent.com/IOAI-official/IOAI-2026/e1963801aa4cf33a5a03520b39fa6620a7894c54/Individual-Contest/2_Robot_Chasing/statement.md)은 배열의 축·범주와 ID 등 별도 입력의 관계를 읽게 한다. 둘은 국제 고등학생 개인전 자료이지 국내 중등 기출이 아니다. [pandas loc](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.loc.html)의 조건 선택과 [iloc](https://pandas.pydata.org/docs/reference/api/pandas.Series.iloc.html)의 위치 선택이 이 예의 연산 근거다.

평균 대체의 훈련·검증 경계도 비교했다. 기존 기기 검증의 signal에 결측이 없어 검증 전체로 새 평균을 잘못 학습해도 예측값만으로는 드러나지 않는다. V7 signal을 사본에서 결측으로 바꾸면 훈련 평균 4와 검증 평균 5.5가 다르고, 검토용 최근접 중심 모델의 V7 예측은 정상/점검으로 달라지나 검토용 결정트리는 양쪽 모두 점검이다. 따라서 예측이 같아도 전처리 상태 확인이 필요하다. 그러나 2주 본문에는 검증 결측과 훈련 전용 대체의 구체적 설명·독립 문제가 이미 있으므로 이것을 전 과정의 신규 누락이라고 단정하지 않았으며 이번 1주 필수 문제로 추가하지 않았다. 점수만으로 구분이 어렵다는 뜻이지 기록된 대체값이나 코드를 보면 판별할 수 없다는 뜻은 아니다.

## 독립 시험 결과

[재현 코드](audit.py)와 [결과](audit-final.json)는 최종 노트북의 실제 완성 예제 셀을 사용한다. 검증기는 `--base-ref`를 받아 이전 후보의 Git ref를 바꿀 수 있으며 기본값 `eb154346…`은 이 로컬 재구성에서만 존재할 수 있다. 정상 데이터와 행을 섞고 pandas index를 비연속 또는 중복 라벨로 바꾼 표에서 ID별 잎 관찰이 유지됐으며, P02의 열 한 칸은 `(2,2,2)`, 노란 잎 수는 1이었다. 관찰 열 자체는 이 예에서 shape `(6,)`의 object Series다. P02 ID를 빼거나 중복하면 명시적 오류가 발생했다. 꺼낸 배열 사본을 바꿔도 표와 원래 사전이 바뀌지 않았고, 설명용 표의 배열을 바꿔도 원래 사전은 유지됐다.

기준 대비 학생 노트북 46개 셀의 ID·순서는 같고 소스 변경은 `deep-count-intro`, `deep-count-code`, `303c6117`, `4042bdda` 네 셀이다. 기기 입력·정답 공개 단계·학생 빈 답안과 영역 입력·답안은 보존됐다. 8절에는 기존 안내를 지우지 않고 완료/미완료·답안 위치·받은 도움·다음 할 일 기록란이 추가됐다. 이 기록은 숙달 평가가 아니며 시간 지정은 없다. Markdown 변환으로 표의 활동 12행과 제목이 분리됨을 확인했다. 이 확인은 전체 HTML 브라우저 표시 검사가 아니다.

교사용 경로표에 나온 본문 과제 C/D/E 등 주요 셀 ID 10개를 실제 제목·내용과 대조했다. 기존 본문 96셀과 교사용, 교량 및 정답 CSV는 기준과 바이트가 같고, 검토 시점 2주차 및 10주 계획에 변경은 없었다. `deep-count-code`의 저장된 출력은 독립된 실제 코드 실행 출력과 정확히 일치했다. 별도로 남겨진 최종 실행 로그는 같은 노트북 SHA에서 코드 셀 22개가 통과했음을 기록한다. HTML SHA-256 `4ab46a7834892af8b295cc627cf03be4779fdb5cbe91afc408d657a84d4f4f42`를 확인하고 기록란 12행, CSV·본문·교량·문제 보충 네 상대 링크와 새 출력 문자열을 점검했다. HTML 전체의 실제 브라우저 표시는 확인하지 않았다.

코드 통과는 완성 예의 동작과 일부 경계의 증거다. 학생이 기기 문제를 독립적으로 풀었다거나 실제 학습 부담·소요 시간이 적절하다는 뜻은 아니다. 기존 본문 교사용의 검증 파일 동봉 여부에 관한 불일치는 이번에 건드리지 않았다.
