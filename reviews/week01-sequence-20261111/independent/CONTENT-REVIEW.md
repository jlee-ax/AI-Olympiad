## 실제 계산·반례와 검출 주체

동결 새 입력의 유효 개수는 `[3,2]`, 합은 `[[4,4,10],[1,-1,3]]`, 평균은 `[[4/3,4/3,10/3],[1/2,-1/2,3/2]]`이다. 실제 교안 `lookup_and_masked_mean`의 조회 배열·mask·합·개수·평균 전부를 독립 루프 구현과 대조했다. 작은 값에 절대 허용오차 1e-12를 쓰며 ID/shape/count는 정확히 확인했다.

실제 B 준비 경로 `2→14→16→22→24→31→33`은 새 커널에서 작동한다. B의 Q는 `[[2,3],[3,2]]`, raw ID는 `[8,90]`, cosine ID는 `[53,90]`이다. 후보 공동 순열 뒤 위치 `[0,1]`, 올바른 ID `[53,90]`, ID를 움직이지 않은 오류 `[90,8]`도 재현했다. 토큰 빈도 행렬을 통한 대안 평균도 같은 값을 냈다. 이는 검토자가 빈 B를 푼 참조 해답이며 학생 답안/성취가 아니다.

`functional-results.json`의 33개 유효 판정은 정상24개, 실제 helper 단일 오류8개, 오류가 가려지는 대조1개다. 8개는 T분모, 비영 PAD 포함, 정상 영벡터 제외, 반복 중복제거, 음수허용, 잘못된 축, all-PAD를 관측0으로 처리, 정상 영평균 거부다. 모두 기대대로 검출했다. 변이24셀은 실제 FunctionDef를 AST로 추출해 한 군데만 바꾸며 예제 assert는 실행하지 않는다. **검출 주체는 학생용 자동 채점기가 아니라 검토자 오라클**다. 원시 traceback과 실제 값은 각 runs의 result.json에 보존했다. 잘못된 축의 (4,3)/(2,1) broadcast 오류와 영평균 거부는 주입한 수학·계약 결함 자체에서 발생했음을 읽었다.

PAD를0으로 바꾸고 분모T=4를 잘못 쓰면 평균 좌표는 틀리지만 각 행이 옳은 평균의 양의 배수다. 실제 변이 함수의 평균 `[[1,1,2.5],[.25,-.25,.75]]`는 잘못됐는데도 전체 cosine 점수와 최종 ID가 같았다. 이 대조의 passed는 잘못된 평균 승인 뜻이 아니라 **cosine/ID만 검산하면 놓친다**는 기대의 성공이다. 좌표·개수·합을 따로 확인해야 한다.

통합본 전체18코드, 최종 bridge 전체16코드를 실행하고 저장 텍스트/표시 유형을 대조했다. 통합 PNG 존재 및 실제 `result.csv` 파일의 notebook 단계 쓰기·재읽기를 확인했다. 기존 본문6개 준비/제공 코드 경로와 A도 실행했다. 빈 셀은 완료로 세지 않는다. 검토자 기기 문제의 중심 모델 검증2/3와 깊이2 트리 검증1은 서로 다른 합리적 해답을 수용하는 예이며, 미상 라벨 제외/훈련 평균4와 요청 ID CSV 순서도 확인했다. 이 참조 해답은 실제 학생 작성이나 교안의 자동 문제 해결이 아니다.

## 실패 보존과 범위 한계

첫 A 오라클은 과거 답안 위치27을 재사용해 현재 입력 셀을 빈칸으로 검사했다. 행렬 계산은 맞았으며 이는 교안 결함이 아닌 검토기 오류다. 원래 script/result와 `invalid-A-oracle-adjudication.json`을 보존하고 새 v2/최종 A 실행으로 정정했다. 내용 감사 초안도 raw JSON list-of-lines와 nbformat 정규 문자열 비교 차이로 실패했다. 기존 script와 `invalid-content-audit-adjudication.json`을 남기고 새 v2에서 양쪽 정규화 후 통과했다. 실패를 정상으로 덮어쓰지 않았다.

HTML은 파싱/핵심 문구 동기화만 검사했고 브라우저 시각 렌더링은 미검증이다. 일반 Jupyter/Colab의 소켓 기반 실행·숨은 테스트·전체 수치 영역·실제 학습자의 이유/도움/오해/성과·새 범위 시간 및 10주 전체 적용은 미관찰이다. 공개 teacher 파일은 권한으로 숨겨진 답안이 아니므로 독립 수행 운영 시 별도 접근 관리가 필요하다. 기존 사용자 미커밋 원문/과거 기록/교안/인덱스/원격은 수정하지 않았다.
