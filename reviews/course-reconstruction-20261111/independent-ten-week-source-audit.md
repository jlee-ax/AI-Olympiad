# 10주 과정: 독립 원문 조사와 선수관계 검토

작성일: 2026-11-11. 이 문서는 공식 문제의 요구와 대학·기술문서의 원리에서 출발한 **교육 설계 제안**이다. 별도의 출처 조사이며 교안이나 학생 답안을 실행·채점한 결과는 아니다.

## 기준, 자료 상태와 해석 범위

- 출발점은 `reviews/discovery-loop-20261111/review.md`, `source-research.json`, `runs/final-report.json`이다. 기존 조사 12개 원문과 구분하여 아래 자료를 다시 검색·직접 읽었다. 최종 보고서는 14개 요구 중 **13개를 열린 큐**로 남겼다. D03의 현재 1주 국소 사례가 설계됐다는 사실은 다른 과제군에 대한 전이나 전체 과정 달성을 뜻하지 않는다.
- [현재 계획](../../curriculum/student-plan.html)과 [계약](../../curriculum/contract.json)은 중등 대상, 주당 수업 120분과 별도 필수 자습을 전제로 한다. 계약의 60개 항목은 `scheduled_only`이며 편성 자체는 제작이나 숙달의 증거가 아니다.
- 비교 대상으로 지정받은 별도 보존 worktree `ai-olympiad-week01-integration`의 실제 1주 노트북은 91셀이다. `validation.json`에는 28개 코드셀의 새 in-process 커널 실행·오류 0, 노트북 SHA-256 `733c0093b44f30d31354567331c2c39ee325ed074e7a6368bb1f2e96f0c174c0`, 학생 답안 미평가와 시간 미관찰이 기록돼 있다. 이는 노트북 실행 검증이며 학습효과 검증이 아니다. 검토 시점에 지정된 보존 worktree에서 실제 2–10주 교안은 찾지 못했고 계획 HTML의 학습 자료 칸도 비어 있었다. 이 진술은 검토 시점의 관찰이다.
- 기본 코딩을 해 본 중학생에게는 일단 표의 행·열, 평균, 비율, 조건, 함수와 파일을 사용해 작은 입력으로 원리를 연결하는 것이 전이 제안이다. 국제 문제 전체를 같은 난도로 즉시 해결해야 한다는 뜻이 아니다. 본문 숫자·표·평가 아이디어는 독자적으로 축소한 교육 사례이며 공식 기출문제 또는 공식 정답이 아니다.
- 계획된 별도 자습은 2주 6–8시간, 3주 7–9시간, 4–5주 각 8–10시간, 6주 10–14시간, 7주 14–18시간, 8–9주 각 16–20시간, 10주 10–14시간이다. 이는 계획 추정치이지 초보 학생의 실제 소요시간이나 실현 가능성을 입증하지 않는다. 1주의 이전 5–7시간은 수정된 숙제의 실측치가 아니다.

- [KOAI 2026 예시 공지](https://kitpa.org/files/36) L87–96에 따르면 예시는 고등부 기준의 학습 참고이고 정답이 공개되지 않았으며 난도 순이 아니다. 2026 당시의 중등 범위·문항 구성도 그 해의 사실이다. 해당 공지는 교육기관 등의 문제 이용 시 사전 사용허가를 명시한다. 아래는 원문 위치를 링크한 분석과 독자 합성 과제이지 원문 문항의 재배포가 아니다.

## 가장 먼저 보완할 교안 단위

**2주차의 ‘예측 시점 → 그룹 분할 → 훈련만 fit → 라벨 의미 → 검증 지표’ 종단 실습과 독립 평가**를 우선한다. 1주 실제 교안은 이미 행·열·결측·예측 시점을 시작했고, 이 단원은 3–9주 모델 선택과 전처리의 공통 선수다. 9주 검색 행렬이나 8주 embedding보다 시간상 선행하며, 기존의 D06/H01/H02와 새 Antique·Ghost 반례가 각각 다른 방식으로 필요성을 지지한다. 이 단원만으로 2주 계획의 ROC, 다른 전처리, 시계열, 전 과정을 완료했다고 판정하지 않는다.

기존 계획의 120분 배치를 유지할 수 있는 초안은 이론 30분(정보 시점·라벨·분할), 비코딩 30분(그룹과 혼동행렬 20분, 필기 10분), 코딩 60분(분할 20분, 전처리 pipeline 20분, dummy 검증 20분)이다. 이후 별도 자습에서 ROC와 다른 처리·시간/그룹 분할을 다룬다. 각각의 실제 소요시간과 학생 이해는 확인되지 않았다.

### 독자 합성 사례와 독립 평가 후보

- 훈련 그룹 A의 `(수치, 라벨)`은 `(2,-1), (4,-1)`, 그룹 B는 `(6,+1), (결측,+1), (8,0)`이다. 이 사례의 명세에서 `0`은 미상이며 −1과 +1만 알려진 라벨이다. 검증은 별개 그룹 C `(20,+1), (결측,+1)`와 D `(10,-1), (12,-1)`이다. 테스트 그룹은 4주 필수 자습의 모든 모델 선택이 끝날 때까지 공개하지 않는다.
- 교육용 단순화로 **알려진 라벨의 훈련 행만** 전처리 fit에 사용하는 규칙을 사전에 정한다. 따라서 결측 대체 평균은 `(2+4+6)/3=4`; 검증 결측도 4로 대체한다. 만약 알려진 훈련·검증의 값 전체를 섞어 fit하면 `(2+4+6+20+10+12)/6=9`가 되어 평가 정보가 통계에 들어간다. 이 사례에서 0은 정답 클래스가 아니다. 다만 명세가 허용하는 준지도/비지도 방식에서 미상 **훈련 특성**을 이용하는 것은 별도 선택이므로 이를 모두 금지하는 규칙으로 가르치지 않는다.
- 구현 과제는 그룹 ID 교집합 검사 → 알려진 라벨의 훈련 행 선택과 정답 열 제외 → `SimpleImputer`와 `StandardScaler` 및 `DummyClassifier`를 `Pipeline`으로 묶어 훈련에만 `fit` → 검증에 `predict` → 라벨 의미·통계·행 대응 점검이다. 이것은 학습용 설계이며 위의 공식 문제 baseline 복제가 아니다.
- 독립 새 입력으로 훈련 관측값 `[3,6,9]`, 검증의 관측값 99와 결측을 주면 정당한 훈련 평균은 6이고 잘못 합쳐 계산한 평균은 29.25다. 그룹이 겹치는 분할과 예측 후에만 생기는 열을 진단하고, 예시 코드를 가린 뒤 자기 코드와 이유를 기록하게 한다.
- 새 정답 `[+1,+1,-1,-1]`과 예측 `[+1,-1,+1,-1]`의 TP·FP·FN·TN은 각 1, 정밀도와 재현율은 각 1/2다. 전부 −1을 예측하면 재현율은 0이고 정밀도는 0/0으로 정의되지 않는다. 실제 라이브러리의 경고/기본 반환값은 별도 확인한다. 도움 여부와 새 입력에서의 실패 이유를 남기되 학생의 결과가 생기기 전에는 달성으로 표시하지 않는다.

## 추가로 확인한 2024년 실제 과제

[IOAI 2024 공식 대회 안내](https://ioai-official.org/2024-tasks/) L65–72는 Scientific Round의 팀 단위 현장 단계와 세 문제를 설명한다. 이 과거 국제 대회를 2025·2026의 개인전, 또는 KOAI 중등 시험과 동일시하지 않는다. [Lost in a Hyperspace 원문](https://raw.githubusercontent.com/IOAI-official/IOAI-2024/main/On-Site-Round/Lost_in_Hyperspace/Lost_in_Hyperspace.ipynb) L19–41, L79–95, L106–114, L234–250, L270–306, L328–353을 직접 읽었다. 입력은 5×5×5×6 배열이고 목표는 세 연속 속성 예측이다. 특성 생성은 속성별 최대 300개, 모델은 고정된 선형회귀이며 검증자료로 훈련하지 않는다. 공식 helper는 속성별 RMSE에 각각 정해진 계수를 곱한 뒤 세 값을 평균한다. 특성 생성·학습·추론에는 속성별 5분 CPU 제한이 있다.

1주 축·평균 → 2주 분할·fit 경계 → 3주 RMSE와 속성별 척도 → 5주 차원 축소 → 10주 출력·시간 제약으로 역추적할 수 있다. **교육용 새 예:** `[1,3,5]`와 `[5,3,1]`은 평균과 최댓값이 같지만 첫 원소는 다르다. 순서가 바뀌어도 목표가 불변이라는 조건이 없으면 평균/최댓값만으로 원래 순서를 복구할 수 없다. 새 데이터에서 통계량을 손으로 계산하고 NumPy로 검증한 뒤, 특성 손실이 예측 목적에 중요한지 설명하는 과제를 제안한다. 이는 축소된 전이이며 국제 과제 해결이나 평가 결과를 보증하지 않는다.

원문의 서술부 L41은 세 개의 `ml_feature_*.txt`를 언급하는 반면 helper 코드 L340–353은 ID와 세 예측을 담은 `predictions.csv`를 쓴다. 둘이 같은 제출 계약이라고 간주하거나 어느 하나가 실제 최종 규칙이었는지 단정하지 않는다. 자료와 모델을 실행하거나 대회 환경에서 이를 해결한 것은 아니다.
