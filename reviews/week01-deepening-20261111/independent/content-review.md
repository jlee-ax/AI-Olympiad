## 내용 판정

이번 후보는 사전 선택한 ‘여러 필드의 뜻·축에서 표현을 만들고 학습에 연결하는 독립 전이가 미평가’라는 공백을 **교육설계 수준에서 보완했다**. 차단할 기술적·명세상 결함은 이번 유한 범위에서 재현되지 않았다. 이는 학생의 실제 전이·숙달이나 10주 목표 달성 판정이 아니다.

평균이 대표 중심이 되는 이유는 구체 후보 0/10/20의 제곱편차합과 `2(m−10)²+200`의 고등학교 대수로 설명한다. 클래스별·열별 평균과 제곱거리도 실제 X/중심/P05 계산으로 이어진다. 이를 모든 분류기의 전역 최선이라고 주장하지 않는다. 범주 숫자의 평균·거리를 자동으로 물리적 의미로 받아들이지 않으며, 수치 특징을 만들 때 잃는 위치 정보와 상대 척도의 영향도 밝힌다. 대학 과정의 미분·고급 영상모델까지 첫 주에 요구하는 것은 적절하지 않아 통과 조건으로 추가하지 않았다.

## 실행과 오류 변이

`candidate-functional-results-v1.json`: 정상 control 12건 통과, 의도 오류 8건 검출. **각각 별도 subprocess와 새 in-process 커널**이었다. 전체 38셀 중 18개 코드셀을 순서대로 실행했다. 18에는 주석만 있는 학생 답안 셀36이 포함되며 이를 독립 풀이로 세지 않는다. 원본의 저장 텍스트/출력 타입이 일치하고 PNG도 저장/생성돼 있다. 생성 산점도는 직접 시각 확인했으며 한글·축·단위·ID·6개 점을 읽을 수 있었다.

실제 `count_yellow_leaf`는 유효한 이진 `(2,2,2)` 관찰 256개를 별도 중첩 루프와 대조했고 배경 색·공간 전치에서 의도한 개수 불변을 확인했다. 새 ID/사전 삽입 순서, 훈련 공동 순열, 검증값999는 실제 셀22·24·26의 계산 구문을 재사용해 점검했다. 어댑터는 고정 화분 초기화·출력·그 화분에 한정한 assert만 제외했다. 교안의 변환 구현을 검토자가 다시 써서 성공시킨 것으로 바꾸지 않았다.

8개 변이는 모두 **실제 후보 코드에 적용한 독립 복사본/메모리 패치**이다. 교안 원본은 변경하지 않았다. 4개는 교안 자체 assert(색만 세기, 잎만 세기, 0을 결측으로 버리기, 전체 자료로 대체 fit)가 검출했다. 다른 4개는 독립 oracle(중심 하드코딩, 사전 순서로 이미지 연결, ID와 예측 값 불일치, 물리 파일을 메모리로 대체)이 검출했다. 기대값·실제값·실패 위치·raw traceback·검출 주체는 `mutation-adjudication.json`에 개별 기록했다. 단순 nonzero 반환만으로 성공 판정을 내리지 않았으며 raw 실패 원인이 해당 변이의 의미와 일치하는지 읽었다. **8건 검출은 교안 자체가 모든 오류를 자동 검출한다는 뜻이 아니다.**

## 참조 해답과 학생 과제의 구분

`preparation-*-result.json`은 후보 전 검토자 소유 새 명세를 중심/3NN으로 푼 참조 코드의 검산이다. `runs/reviewer-exercise/result.json`은 후보의 실제 새 기기 입력을 검토자가 별도로 구현해 중심/결정트리로 푼 결과이다. 이 두 lane은 실제 후보의 집계/변환 함수를 실행한 `native-aggregation`/`native-conversion`과 다르며 학생의 성취도 아니다.

새 기기 참조에서 알려진 T1–T4의 signal 관측 평균은 2이고 T5의 ?는 제외된다. 중심 검증은 [정상,점검,정상], 2/3이며 트리는 [정상,점검,점검], 1이다. 요청 N7,N3,N1에서 중심은 [점검,점검,정상], 트리는 [정상,점검,정상]이다. 교사 해설의 중심 결과와 다른 모델 허용 원칙 모두 재현됐다. 트리의 높은 점수는 작은 검증에서의 결과이며 현실 성능이나 최종 테스트 성능을 뜻하지 않는다.

동결한 별도 새 명세의 네 특성(숫자·격자 집계·zone one-hot) 전체는 **검토자의 참조 해답**이다. 후보의 실제 함수에 직접 넣은 격자는 그 함수가 약속한 잎 코드로 인코딩한 부분 기능 시험이다. 후보가 일반적인 임의 스키마·one-hot 파서를 제공한다고 주장하거나 zone 처리가 교안에서 자동 검증됐다고 부르지 않는다.

## 남는 필수 과제와 실제 부담

후보의 셀37은 원본 별도 새 커널의 준비3→CSV27→새 입력54와 각 과제의 의존 예제, bridge 준비2→독립 입력21/25→답안23/27을 안내한다. 독립 실행한 8경로는 Python 진단, dtype/평균, 배열, 두 그래프 라이브러리, 새 CSV 준비/병합 자료, 내적, bridge A/B다. 빈 셀24/61/66/81·23/27 등은 실행돼도 주석뿐이므로 학생 풀이 미관찰로 기록했다. merge 예제는 site_notes 준비까지이며 학생의 실제 join·키 오류 처리가 완성됐다고 세지 않는다.

이전 34/16에서 38/18로 늘었지만 셀 수는 실제 부담의 측정값이 아니다. 추가된 축·범주 조건, 두 특성 거리, 중심의 이유 및 바뀐 독립 표현은 기존 화분 흐름 안에서 연결됐고 기존 완성 예제 재낭독 대신 새 입력 연습으로 가도록 안내한다. 그러나 필수 A–E/A·B 왕복·직접 풀이가 남아 있어 기존 5–7시간 추정을 새 범위의 실측 시간으로 사용할 수 없다. 교사 자료는 이를 명시한다. 실제 120분 운영 가능성·학생 소요시간·도움·성취는 여전히 미관찰이다.

2주 기존 고정 z점수/temporal score는 학습된 분류기라고 바뀌지 않았다. 2주 전처리/분할/평가, 3–5주 손실·거리/모델, 6주 텐서, 7–9주 실제 영상/텍스트/오디오 모델과 ID, 10주 핵심 완성 코드 없는 새 명세의 선수 연결은 유지된다. 이 첫 주 설계는 그 후속 과제의 실행·숙달 증거를 대신하지 않는다. 10주 전체의 시간·숙달·합격 가능성은 이 검토로 확인하지 않았다.

## 재현·범위 제한

raw 결과와 실패는 `runs/<case>/result.json`/`process.json`, 입력 패치는 `case-configs/`, 코드 출처는 oracle 파일/구문 해시로 보존한다. 모든 run은 원본 SHA 불변과 runtime 삭제를 확인했다. 학생 notebook/HTML·기존 기록·index·원격을 수정하지 않았다. 초기 절대경로 설정의 checkout 이동 재현은 별도 `relocation-*` 기록에서 보완할 예정이다. 그 전의 로그와 동결 자료는 덮어쓰지 않는다.

HTML의 18개 코드 입력이 notebook 코드와 일치하고 embedded PNG가 하나 있으며 필수 연결 링크가 있다. HTML 전체의 브라우저 시각 점검, 일반 소켓 Jupyter/Colab, 실제 학생 수행·시간·비공개 테스트는 미검증이다. 금지된 브라우저/커널 정책 우회를 하지 않았다.
