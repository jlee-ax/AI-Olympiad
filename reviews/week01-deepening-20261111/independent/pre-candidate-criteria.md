# 후보 편집 전 독립 검토 기준

기록 시점: 2026-11-11. 이 문서는 현재 자료를 직접 읽은 뒤, 새 교육 후보를 읽거나 실행하기 전에 고정한다. 대상 입력의 정확한 SHA와 셀별 식별자는 baseline-manifest.json에 있다. SHA는 동일 바이트의 식별에만 쓰며 교육적 의미·품질·승인을 판정하지 않는다. 이번 단계는 읽기와 기준 작성이며 실행 시험이나 학생 관찰이 아니다.

## 현재 경로와 근거

학생 시작점 curriculum/student-plan.html의 1주 링크는 week01_integrated.ipynb이다. 현재 통합본 34셀은 화분 표를 읽고 결측·평균·분산·배열·그래프·고정식·학습된 중심·검증·ID 순서·실제 CSV 파일까지 이어진다. 원본의 과제 A–E와 bridge A/B는 통합본 마지막 셀 33이 여전히 필수로 지정한다. 따라서 통합본만 짧아졌다는 이유로 전체 필수 부담이 감소했다고 판정하지 않는다.

셀 번호는 아래에서 모두 0부터 센다. 현재의 정확한 필수 연결은 다음과 같다.

| 목표 | 현재 위치와 연결 | 후보에서 보존·대체 여부를 확인할 증거 |
|---|---|---|
| 함수·반복·평균·빈 입력 | 통합 5–6, 원본 14–25·80–82 | 반환값/누적·분모/결측·0/입력 보존과 새 입력의 학생 답안 |
| 평균·분산 원리 및 단위 | 통합 7–8, 원본 5–12·47–48·67–76 | 기호와 실제 수 대응, 편차·제곱·분모, ddof와 단위, 새 분포·그래프 |
| CSV·열 선택·dtype·결측·오염 단위 | 통합 1–4·25–28, 원본 27·38–44·54 및 A–E | 행/열 계약, NaN/0 구별, 20ml 원문 해석, 누락 열 오류와 물리 파일 재읽기 |
| 배열 축·reshape·broadcast | 통합 9–12, 원본 53–66, bridge 0–15·A/B | 축의 의미와 수축, 다른 값/모양, shape가 같아도 잘못된 계산 반례 |
| 두 시각화 라이브러리·집계·병합 | 통합 13–14, 원본 67–79 및 필수 새 CSV 과제 | Matplotlib/Seaborn 모두의 학생 변경 입력, 분포·집계 단위와 행 보존 |
| 내적·행렬·검색/ID | 통합 15–16·25–28, 원본 83–86, bridge A/B | 같은 순서의 특성·가중치/ID 정렬, 요소곱과 내적, 공동 순열과 ID만의 순열 |
| 실제 fit·검증·낯선 제출 명세 | 통합 17–32 | train-only 통계·모델, 새로운 행/라벨/열/출력 계약, 학습 증거와 독립 빈칸 |

원본 복귀 경로는 새 커널의 준비 셀 3→CSV 27→새 입력 54, bridge는 준비 2와 독립 입력 21/25 및 학생 답안 23/27로 안내되어 있다. 이 경로의 제공 코드만 실행 가능한 것과 학생이 실제로 푼 것은 별도다. 후보가 다른 번호·제목을 안내하면 정확한 새 위치와 필요한 선행 상태를 다시 확인한다. 링크 하나만 존재하는 것은 이행 증거가 아니다.

## 선택한 최우선 공백과 선택하지 않은 주장

현재 통합본은 두 특성 열, 축, 고정 내적을 설명하고 실제 학습은 water_ml 한 열로 수행한다. 독립 기기 문제도 signal 한 열이다. 따라서 학생이 낯선 명세에서 여러 필드의 역할·사용 가능 시점·수치/범주 의미·배열 축을 결정하여 모델 입력으로 변환하는 독립 전이는 현재 평가되지 않는다. 이 연결을 하나의 자료 흐름 안에서 분명히 하는 것을 최우선 개선 대상으로 선택한다.

이는 단일 특성 중심 모델이 가짜 학습이라는 뜻이 아니다. 훈련값 변경에 따라 중심·대체 통계·예측이 달라지는 현 예는 타당한 입문이다. 두 검증 행이 모두 양성이고 정확도가 1/2인 작은 예도 한계를 밝히면 기초 설명에 쓸 수 있다. 초급 교안이 공식 전체 대회나 10주 숙달을 이미 완성해야 한다고 요구하지 않는다.

기초 함수·평균/분산·CSV·그래프·배열·ID 연습을 삭제하거나 1주 밖으로 밀어 얻은 겉보기 간결함은 이번 개선으로 세지 않는다. 반대로 모든 고급 필드 인코더, 반지도학습, 영상·문장 모델, 미분 증명, 여러 분류기를 1주 필수에 더하는 것도 요구하지 않는다. 부담은 통합본과 남아 있는 필수 후속 과제 전체로 판단한다.

## 고정할 내용 판정 기준

1. **문제 계약.** 예측 대상·관측 시점·사용 가능한 입력·정답 도착 시점·평가 단위·출력 규약을 표나 짧은 말로 복원할 수 있어야 한다. 수치 0, 결측, 미상 정답, 음성 정답을 계약별로 구분한다. 모든 문제에 동일한 그룹/시간 분할을 강요하지 않으며 실제 독립성·미래 예측 계약으로 판단한다.
2. **이론과 계산.** 핵심 수식은 구체 값→기호와 인덱스/합계·분모/단위→작은 손계산→코드로 연결한다. 평균·분산·축 평균·내적의 무엇을 더하고 나누는지, 결과가 어떤 대상의 값인지 설명해야 한다. NumPy 1D 배열과 수학의 행/열 벡터를 무심히 같은 shape로 취급하지 않는다.
3. **초심자 발판.** Python 선수는 계획에 적힌 변수·조건·반복·함수·리스트·파일/오류 범위로 둔다. 처음 나오는 배열 축·범주 코드·모델 API에는 작은 중간 결과와 그 의미를 제공한다. 이미 한 단순 계산의 모든 줄을 반복 증명할 필요는 없으며, 복잡한 모델 내부 증명을 입문 통과 조건으로 삼지 않는다.
4. **실제 학습.** 고정 계산식, 훈련에서 얻은 전처리 통계, 정답을 이용해 fit한 모델을 분리한다. 코드에 fit이라는 이름이 있다는 사실보다 학습된 값과 훈련 변경의 영향을 본다. 모든 훈련 변경이 반드시 모든 질의 예측을 바꿔야 한다는 잘못된 조건은 쓰지 않는다. 단순한 합리적 모델도 허용한다.
5. **fit·평가 경계.** 전처리와 모델은 계약상 허용된 훈련 자료에만 fit한다. 검증 자료는 정해진 모델 비교에 쓸 수 있지만 반복 선택의 한계를 설명한다. 최종 테스트 결과로 다시 설정을 고르지 않는다. 결측 대체는 원래 정답 복원이 아니며 새 범주 정책은 명시한다. 2주 고정 점수·임계값 계산을 학습된 분류기라고 부르지 않는다.
6. **다중 필드와 축.** 표의 행과 특성 열, 필요 시 공간·채널 축의 의미를 이름/단위로 연결한다. 코드가 실행되고 shape가 맞아도 열 순서나 ID 대응이 바뀌면 틀릴 수 있음을 확인한다. 수치로 저장된 범주를 크기·거리로 해석할 근거를 묻되, 모든 모델에서 숫자 코드 사용을 금지하지 않는다. robot_id처럼 문맥상 유용한 개체 정보와 단순 제출 ID를 구분한다.
7. **문제 전이.** 낯선 열 이름·라벨·값·행 순서·출력 명세에서도 필드 역할과 전처리/모델 입력을 재구성하게 한다. 표면적인 파일 이름 변경이나 완성 코드 재실행만을 독립 전이로 세지 않는다. 정해진 중심 모델과 예측이 다르다는 이유만으로 다른 정당한 분류기를 오답 처리하지 않는다.
8. **정확한 수학 범위.** 유효한 입력의 범위, 빈 입력/전부 결측, ties와 0분모 등 설명에 필요한 경계를 점검한다. 현 observed_mean의 ±1e6·길이≤10000 계약을 전 유한 실수 범위의 안정성 주장으로 확장하지 않는다. 합·지표의 부동소수 계산에는 필요한 허용오차를 쓰고, 임계값의 실제 포함 관계는 흐리지 않는다.
9. **파일과 정렬.** 메모리 CSV 변환과 실제 파일 저장·재읽기를 구별한다. 행 수·ID 일치·중복/누락·정답 라벨 집합·header/열 순서/파일 이름을 현재 명세로 검증한다. 리뷰 oracle의 파일 I/O를 교안의 I/O로 잘못 세지 않으며 실행 단계·파일명을 분리한다.
10. **필수 범위와 부담.** 새 흐름과 기존 A–E/A·B가 어느 목표를 각각 담당하는지 위치로 매핑한다. 2주 전처리/평가, 3–5주 모델·거리/손실, 6주 텐서, 7–9주 실제 모달리티 모델, 10주 핵심 완성 코드 없는 새 문제의 선수 관계를 보존한다. 1주 역사적 5–7시간 추정이나 셀 수로 실제 부담을 확정하지 않는다. 새 API·새 표현·독립 과제·필수 왕복 경로를 함께 따져 설계상 부담을 설명한다.
11. **설명·노출·주장.** 학생 문서에는 학습에 필요한 문제 지시·실행 방법은 두되 교사 운영 시간·내부 검증 상태를 넣지 않는다. 교사 답안은 공개 저장소만으로 비공개가 보장되지 않는다. 빈 답안의 존재, 자동 테스트 통과, 교안 이해 가능성, 학생의 독립 성취, 실제 수행 시간은 서로 다른 관찰 수준으로 기록한다.
12. **판정의 강도.** 기술적 오류/명세 모순, 교육적 범위 공백, 개선 제안, 미관찰 상태를 구분한다. 예제가 소형·단일 특성·낮은 검증 정확도라는 이유만으로 탈락시키지 않는다. 공식 범위를 축소한 예는 축소점과 다음 경로를 정직하게 밝히면 허용한다. 완전한 대회 해결·숙달이라는 주장이 있으면 그 강도에 맞는 별도 증거를 요구한다.

## 후보 수령 뒤 독립 기능 입력과 오류 변이 계획

아직 실행하지 않았다. 각 검증은 새로운 subprocess에서 시작하고 그 안에서 새 in-process 커널을 만든다. 원본과 정상 control을 먼저 성공시킨 뒤 변경 하나씩 비교한다. 실패·harness 결함도 보존하며 잘못된 초기 결과를 조용히 덮어쓰지 않는다. 후보의 계약을 벗어난 입력은 범위 밖으로 따로 기록한다.

| 검증군 | 독립 정상 입력/대조 | 의도적 오류 및 판정 범위 |
|---|---|---|
| P01 산술·결측 | 작은 리스트 손계산, None/NaN/0, 빈/전부 미상, 명시된 범위 끝 | 0을 제거, 전체 행 수 분모, 합계/개수 오염. 범위 밖 값을 필수 성공으로 강요하지 않음 |
| P02 축·배열 | 비정사각형 새 배열·단위/축 이름, 루프/별도 구현 비교 | 축 교환, reshape를 transpose로 간주, shape만 같은 요소곱/내적, 잘못된 broadcast |
| P03 필드/시점 | 역할이 다른 여러 필드·새 헤더, 사용 가능 시점 설명 | 정답/미래 관측을 특성으로 사용, 범주 코드를 무근거 연속량으로 설명. 모델 성격에 따라 판단 |
| P04 fit 경계 | 훈련값/라벨 변경과 검증값 변경을 분리, 실제 학습 상태 확인 | 전 자료 대체/스케일 fit, 검증 정답 학습, fit 무시 고정식. 단순 ID를 정답 지름길로 사용 |
| P05 정당한 대안 | 최소 다른 합리적 분류기 하나, 같은 훈련·검증/출력 계약 | 중심 예측과 다르다는 이유만의 부당한 오답 처리, 정답 하드코딩으로 형태만 충족 |
| P06 순열과 ID | 특성 행·정답·ID의 공동 순열, 임의 문자열/정수 ID | ID만의 순열, 누락/중복/NaN ID, 열 순서 불일치, 값만 맞고 사람/표본 대응 오류 |
| P07 제출/파일 | 현재 계약의 실제 임시 파일 저장·재읽기·정리, 별도 oracle I/O | 메모리 왕복으로 대체, 잘못된 header/이름/열/행 수/라벨. 교안 파일과 oracle 파일을 구별 |
| P08 필수 경로 | 안내된 원본/bridge 준비와 제공 코드를 각각 새 프로세스에서 실행 | 누락 선행 변수, 잘못된 셀 위치, 다른 표 스키마 섞임. 빈 답안은 학생 미수행으로 남김 |
| P09 전이 설명 | 새 명세에서 표현·축·정답·split·출력을 설명한 reviewer 해답 | 단순 실행 성공만으로 모든 교육 목표/학생 성취를 인증하는 오류를 거부 |

Robot을 쓰는 후보라면 독립 스냅샷/무이력, 행·열·채널, 별도 direction, carrying null의 의미, 개체마다 일관된 차이, 숫자로 저장된 category의 의미를 우선 반례로 본다. 영상·자연어 전 모델을 1주에서 구현하도록 요구하지는 않는다.
