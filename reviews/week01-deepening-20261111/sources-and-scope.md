## Priority and proposed integrated path

**First priority: meaning → permitted operation → representation → learned model → evaluation/output, followed by an independent new contract.** A small object/colour grid attached to the existing synthetic plants can supply a meaningful raw-input stage: identify leaf AND yellow cells, sum the spatial axes to produce a count, combine that feature with water, and continue through actual fitting and CSV verification. This is an educational synthesis, not an official Robot solution.

The essential theory is that numeric storage does not make a category a measurement. Averaging object codes or counting colours without object conditions can be semantically wrong despite valid shapes. Reducing spatial axes discards positions. An arbitrary record ID is not automatically an explanatory feature, but the plant example must not become a universal rule excluding all IDs: Robot's robot identity is a counterexample.

Use the two-feature model as the final worked path rather than duplicating full one-feature and two-feature training loops. A brief one-feature distance calculation can remain as a prerequisite. For two features, connect each class/feature mean to a coordinate, then add the squared coordinate differences. Any fixed `/10` conversion must be described as a chosen reference scale, not a learned optimum. Consistent rescaling of the only feature preserves nearest-centre order; rescaling just one of multiple features can change that order.

**Second priority: what a summary learns and loses.** A small calculation can connect variance to a representative centre: for `[0,20]`, squared-deviation sums at candidate centres 0, 10, 20 are 400, 200, 400. Classes `[0,4]` and `[1,3]` both have centre 2 but variances 4 and 1. Mean-centre fitting does not directly minimize classification error, and equal centres can lose useful distinctions. Full objective-function proofs, gradient descent, and model selection should remain later.

Independent tasks should require the learner to write the field dictionary and prediction-time availability before receiving a worked translation, then create features, fit a legitimate classifier, inspect its learned state, evaluate, and serialize in the new contract's order. Change codes, layout, labels or output format rather than only numbers. Save initial reasoning before feedback; after feedback use another input. Include a same-shape axis error and a nuisance-value change whose correct feature should stay unchanged. Permit multiple legitimate algorithms. A bounded Robot contract diagnostic can test the remaining transfer without inventing action labels or claiming to solve its policy.

Small synthetic checks executed during the audit, without writing files: a 2×2×2 categorical grid's object-and-colour count stayed 1 after background recolouring while colour-only count changed 2→3; spatial transpose preserved shape but changed a specified cell; equal-centre/different-variance arithmetic matched expectations. A separate two-feature scale example changed squared distances `[409,6401]` to `[9.04,1.64]`. These are finite design checks, not student results or official-data performance.
