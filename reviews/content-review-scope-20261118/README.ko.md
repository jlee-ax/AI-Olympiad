# 교안 검수 범위와 내용 개편 구조 감사 · 2026-11-18

감사 기준은 main `d886411d9ddbce4de3e41232a62d37d126b788cc`의 tree `8969ffee3b6849a6855452e66e1f3cba9384e99d`다. 이 문서는 확인한 코드 동작과 제안하는 후속 개편을 구분한다. 이번 변경은 잘못된 학생 효과 측정 안내의 정정, 실행 진단 기록과 개선안이다. 운영 코드의 기준 완화·전환이나 교안 내용 편집을 완료했다는 기록은 아니다.

## 1. 이 작업에서 제외할 검증

학생의 학습효과, 실제 선수지식 진단 응답, 도움 없는 실제 수행·지연 전이, 실제 수업 완료 시간, 교사 노동시간은 이 교안 자동 검수에서 수집·검증하지 않는다. 이를 `미검증이므로 다음에 해야 할 일`로 올리지 않는다. 실제 학습 성과를 주장하지 않는다는 제한은 유지한다. 적용 검수 목록은 버전 관리된 작업 목적·편집 행동 규칙으로 정한다. 실패한 항목을 작업자가 임의로 비적용 처리해 통과시키는 기능은 제안하지 않는다. 그런 주장이 교안에 있다면 주장을 정정하는 것이 작업이며 학생 연구를 새로 요구하지 않는다.

대신 검토할 대상은 교안에 필요한 선수 개념과 지원 설명이 있는지, 문제의 조건과 정답이 타당한지, 과제가 요구하는 판단·구현을 교안이 뒷받침하는지, 코드와 자료가 실행되는지다. 새 입력 과제를 검토자가 독립적으로 풀고 실행하는 일은 가능하다. 이것은 학생이 실제로 전이했다는 측정과 다르다. 분량·활동 수·경로·예상 시간은 설계상 비교할 수 있지만 실제 소요시간으로 표시하지 않는다.

## 2. 실제로 재현한 현재 동작

[재현 코드](reproduce.py)와 [결과](reproduction.json)는 기존 저장소의 합성 정상·오류 대조 fixture를 사용한다. 실제 교안 승인, 학생 응답이나 교육자 심사를 만들어 넣은 것이 아니다. 변경 필드의 직접 영향을 보기 위해 합성 검토의 fingerprint를 다시 결합했다.

| 대조 입력 | 현재 실행 결과 | 해석 |
|---|---|---|

| 같은 기록에서 학생 선수지식 응답·증거만 없음 | K04 not_run, ready=false | 교안 설계 검수에 실제 학생 응답 필드가 섞여 있다. |

| 관찰 없이 학습효과 improved라고 주장 | K15 failed | 근거 없는 성과 주장 차단은 유지할 동작이다. 이를 학생 자료 수집 요구로 바꾸지 않는다. |

코드 근거: [K02](../../tools/quality.py), K04의 `observed/help/evidence` 요구, K15의 단원별 calibration과 tolerance, `all(check.status == passed)` 완료식, [발견 루프](../../tools/discovery_loop.py)의 모든 질문·frontier 차단, [workflow](../../tools/workflow.py)의 discovery_unresolved 및 16개 전부 통과 조건이다. 단순 문구 검색만으로 학생 효과가 항상 차단된다고 결론 내리지 않았다.

## 3. 내용 보정이 약해지는 구조

기존에 내용 개선이 전혀 없었던 것은 아니다. [발견 조사](../discovery-loop-20261111/source-research.json)는 12개 원문 출처와 14개 요구를 기록했고, [1주 통합 기록](../week01-integration-20261111/integration-summary.md)은 별도 설명·모델·검증 경로를 재구성한 실제 변경을 남긴다. 이를 새 기능인 것처럼 다시 만들 필요는 없다.

그러나 현재 코드에는 다음 연결이 약하다.

1. **서로 다른 검수 목적이 한 완료식에 들어간다.** 교안 설계, 학생 관찰, 평가기 교정, 외부 탐색이 같은 passed 조건을 공유한다. 관찰 불가 항목과 참고 질문을 해소하느라 내용 편집이 늦어질 수 있다.
2. **발견 요구에서 편집 작업으로 가는 명세가 없다.** discovery는 공백을 기록하지만 다음 행동은 포괄적인 `research_or_refine_and_recompare`다. quality는 이미 등록한 unit/claim의 실패와 문서·증거 보정에 강하며, 새 내용 추가나 여러 절의 교체·통합을 구체적으로 구성하지 않는다. action 문자열로 삭제를 적는 것은 가능하지만 삭제의 선택·영향·완료 조건을 관리하는 구현은 없다.
3. **완료 차단이 수정 시작 차단으로 쓰인다.** 공백이 있는 산출물을 완료 처리하지 않는 것은 필요하다. 공백을 고칠 권한 있는 편집까지 같은 이유로 막는 것은 다른 문제다. 현재 도구들은 자문용이며 실제 검색·편집은 작업자가 수동으로 이어 왔다.
4. **내용을 더하는 것과 덜어내는 것을 함께 평가하지 않는다.** 어떤 능력이 비어 있는지에 더해, 어느 설명·예제가 같은 역할을 중복하는지, 어느 내용이 현재 주차에 과도한지와 제거 뒤 남는 선수·평가 경로를 검토해야 한다. 보존할 이력과 학생이 반드시 따라야 할 본문은 구별해야 한다.
5. **이번 공개 pilot는 내용 개편 능력 시험이 아니다.** 15개 사례는 몇 개의 관찰 필드 답안을 확인한다. 실제 노트북에서 필요한 내용을 더하고 불필요한 내용을 걷어내며 정답·경로를 유지하는 과제를 아직 평가하지 않았다. 정적 문서 점수도 이 공백을 대신하지 못한다.

## 4. 제안: 요구에서 교안 전체의 편집으로 이어지는 과정

### A. 교안 검수와 다른 목적을 나눈다

일반 교안 검수는 내용 정확성, 필요한 범위·깊이, 선수관계, 문제·정답·독립 풀이 조건, 실행, 중복·부담·진입 경로를 대상으로 한다. 학생 관찰은 범위 밖으로 제외한다. K04는 필요한 선수 개념의 설명·지원 경로를 확인하도록 나눈다. K09/T05는 과제 설계·답안 근거를 검사하며 학생의 실제 응답을 요구하지 않는다. K15의 정상·오류 대조는 평가기 버전·분야에 대한 별도 검증으로 관리하고, 변경 영향이 없으면 재사용한다.

참고 탐색과 필수 근거 탐색도 구분한다. 대상 능력·정답·현재 선수관계에 영향을 주는 미해결 사항은 차단하고, 관련 없는 배경 질문은 사유를 기록해 현재 교안 완료에서 제외할 수 있어야 한다. 원문이 해당 주차와 무관하다는 검토 결과도 유효한 종결이어야 하며, 형식을 채우려고 가짜 수요를 만들지 않는다.

### B. 기존 본문과 독립된 요구 목록을 유지한다

현재 발견 루프와 원문 읽기 기록을 활용한다. 공식 범위·여러 공식 과제·필요한 전공 원문에서 요구하는 판단과 구현을 추출하고 `필요 능력 → 선수 능력 → 필요한 설명 깊이 → 확인할 문제`를 묶는다. 자료 수를 채우는 할당량 대신 문제 유형·판단의 다양성과 미해결 범위를 드러낸다. 국내 중등의 지배 범위와 국제 과제의 참고 지위, 입문·후속 주차의 배치를 구분한다.

각 요구를 현재 교안 전체의 설명·활동·과제 위치와 대조한다. 현재 절에 맞는 새 사례만 찾는 흐름을 피하고, 아직 이름 붙이지 않은 개념도 신규 편집 제안의 대상이 되게 한다. 과목 최종 실전 요구를 모든 입문 절에 즉시 강제하지 않는다. 후속 주차로 미룬 필수 요구는 소유 주차·선수 연결·과제를 계속 추적한다.

### C. 추가·제거·교체를 같은 편집 계획에서 선택한다

| 판정 | 편집 행동 | 바뀐 산출물에서 확인할 조건 |
|---|---|---|
| 필요한 능력이나 선수가 없음 | 추가 | 새로운 판단·구현을 가능하게 하는 설명과 확인 과제가 생김 |
| 내용은 있지만 이유·조건·경계가 빠짐 | 심화 또는 교체 | 조건을 바꾼 문제의 풀이 근거와 정답이 유지됨 |
| 같은 능력의 설명·예제가 실질적으로 중복됨 | 통합 또는 제거 | 남은 설명·선수 지원·필수 과제가 보존되고 진입 경로가 단순해짐 |
| 현재 주차에 과도하거나 목적에서 벗어남 | 후속 주차 이동 또는 제외 | 필요한 경우 후속 배치가 실제 경로에 연결되고 현재 선수 경로는 끊기지 않음 |
| 순서가 뒤집히거나 개념이 서로 단절됨 | 재배열·통합 | 사용 전에 선수를 만나고 앞의 설명이 뒤의 판단·코드로 이어짐 |
| 현재 내용이 적절함 | 유지 | 새로운 근거 없이 수정 작업을 만들지 않음 |

각 편집 제안에는 근거 요구, 현재 문제 위치, 선택한 행동과 대안, 변경 후 조건, 영향받는 선수·정답·후속 과제, 검증 방법을 둔다. 한 능력을 위해 추가·제거·재배열을 함께 수행할 수 있다. 기록상 한 가설이라는 이유로 편집을 한 문장 수정에 제한하지 않는다. 실제 교안 diff를 만들고 결과 조건으로 재검토한다.

도표와 수식은 해당 판단을 설명하는 데 필요한 경우 사용한다. 존재 개수나 제목 충족을 내용 깊이로 계산하지 않는다. 반대로 수학적 오류·설명 부족을 놓치도록 관련 검사를 통째로 없애지도 않는다.

### D. 수정할 수 있는 상태와 배포할 수 있는 상태를 나눈다

유효한 기준본·권한·입력·예산과 확인할 대상이 있으면 공백을 해결할 편집 작업을 선택할 수 있어야 한다. 산출물에 미해결 핵심 공백이 있으면 최종 완료·게시 판정은 차단한다. 손상된 입력, 사용자 중지, 권한 부족, 예산 소진은 편집 단계에서도 계속 차단한다. 새 코드가 이 구분을 지원하기 전까지 현재 workflow의 blocked를 자동 실행 허가로 바꿔 해석하지 않는다.

편집기는 수요를 실제 `추가/교체/통합/제거/재배열/이동/유지` 작업에 연결한다. 독립 검토는 실제 변경본 전체에서 해소된 공백, 새로 생긴 오류, 사라진 지원 경로와 남은 중복을 확인한다. 변경과 관련 없는 검증은 재사용하고, 다음 작업은 남은 내용 공백에서 선택한다. 이 과정과 실제 모델·도구 호출을 연결해야 기록만 도는 반복을 피할 수 있다.

## 5. NVIDIA 원본으로 검증할 대상과 지표

NVIDIA의 원래 목적은 스킬 사용 전후의 에이전트 과제 결과를 비교하는 것이다. 원본 Harbor·표준 평가·custom grader를 그대로 사용하되, 과제를 관찰 필드 조회에서 실제 교안 편집으로 바꾼다. 기존 15개 공개 pilot는 연결 검사로 유지하고 성능 평가에서 제외한다.

새 평가에는 최소한 다음 **유형**을 포함한다. 필수 개념이 누락된 자료, 선수가 빠진 자료, 설명이 얕거나 잘못된 자료, 제거해도 되는 실질 중복, 지켜야 할 적절한 기초, 후속 주차로 옮겨야 할 내용, 범위 밖 참고 수요, 의존성을 깨뜨리는 잘못된 삭제다. 이 목록은 과제 수 할당량이 아니다. 실제 문제와 원문을 근거로 독립 작성하고 조정용과 최종 평가용 사례를 분리한다.

요청 산출물은 수정된 교안과 그 근거다. 채점은 의도한 능력 공백이 해소됐는지, 정답·코드가 새 입력에서 맞는지, 보호할 필수 내용과 경로가 남았는지, 불필요한 수정·중복·누수가 생기지 않았는지를 확인한다. 의미 판정은 근거를 읽는 독립 검토가 맡고, 실행 가능한 조건은 실제 코드와 자료로 검사한다. 학생 역할을 흉내 낸 모델의 응답을 학생 성취로 사용하지 않는다.

| 지표 | 측정 대상 |
|---|---|
| 내용 보정 성공률 | 확인된 내용 공백을 수정하고 새 입력·정답 검증까지 충족한 과제 / 해당 과제 수 |
| 잘못된 수정·누락 | 정상 기초를 불필요하게 바꾼 사례, 필수 내용을 지운 사례, 놓친 핵심 공백을 분리 집계 |
| 제거·통합의 보존성 | 제거 뒤 해당 능력의 설명·선수·과제 경로가 끊긴 사례; 단순 삭제량을 성과로 보상하지 않음 |
| 남은 내용과 부담 | 아직 해소되지 않은 핵심 요구, 중복 경로, 필수 활동의 배치와 예상 분량; 학생 시간 실측으로 부르지 않음 |
| 실행 비용 | 실제 측정한 모델·도구 토큰, 시간과 비용 |

같은 자료·모델·도구·예산에서 현재 스킬과 수정 스킬을 비교하고 분모·실패·불확실성을 남긴다. 학생 성적, 교육자 선호 점수, 설명 분량 증가나 정적 점수 상승을 대체 지표로 쓰지 않는다. 허용 가능한 오류와 비용의 판정 기준은 기준 사례를 보기 전에 대상 작업에 맞춰 명시한다.

## 6. 구현 순서와 이번 반영의 경계

1. `quality.py`와 기준 문서에서 교안 검수의 적용 범위를 분리하고 K02의 단계, K04의 설계/관찰, K15의 평가기 교정을 구분한다. 동일 학습자료가 학생 응답 없이 설계 검수를 마치되 근거 없는 성과 주장은 계속 차단하는 정상·오류 대조를 만든다.
2. `discovery_loop.py`에 필수·참고 구분과 근거 있는 제외·종결을 넣고, `quality.plan_work`/`workflow.decide`의 수정 단계와 완료 단계를 분리한다. 위에서 재현한 공백이 구체적인 편집 후보가 되면서 최종 완료는 계속 막히는지 검사한다.
3. 편집 행동, 실제 diff와 변경 후 검증을 연결한다. 정당한 삭제·통합은 수용하고 필수 선수·과제 제거는 거부하며, 원본 이력·사용자 변경·무관한 주차를 보존하는 회귀를 확인한다.
4. 원본 NVIDIA Tier 3의 실제 편집 과제로 스킬의 내용 보정 능력을 비교한다. 격리 실행기·모델 설정이 준비되지 않았으면 실제 실행 횟수를 0으로 보고한다. 이번 감사는 그 실행을 완료했다는 기록이 아니다.
