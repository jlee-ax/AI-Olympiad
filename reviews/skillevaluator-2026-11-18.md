# 교안 작업 스킬과 NVIDIA 평가기 연결 검증 · 2026-11-18

게시 대상은 `main`이다. 아래는 게시 전 고립 작업본에서 확인한 결과다. 비교 기준은 [기존 KOAI 커밋](https://github.com/jlee-ax/AI-Olympiad/commit/4352e266159d2cef9577b79a2d0cafc8b817d375)이며, 두 번 모두 [같은 NVIDIA SkillEvaluator 원본](https://github.com/NVIDIA/SkillEvaluator/tree/e3ede733f4d57578a1630b0579ea236b8cf8a727) 1.0.1을 사용했다.

**확인한 변화는 스킬 문서의 정적 점수와 평가 준비 과정이다.** 각 역할의 사용 조건, 전제, 산출물, 실제 예시와 실패 대응을 명시했다. 공개 문제 15개에 대해 스킬을 주는 경우와 주지 않는 경우를 실제 NVIDIA Harbor 작업 형식으로 준비했다. 실제 에이전트가 교안을 개선한 횟수와 학생 수행 관찰은 모두 0회다.

## 1. NVIDIA가 다섯 지침서를 검사한 결과

| 스킬 | 주로 하는 일 | 정적 점수 전 → 후 / 100 | 이번 원본 보고서의 전체 경고 수 |
|---|---|---:|---:|
| ground | 공식 출처와 수업 조건을 정한다 | 80.8 → 94.5 | 10 |
| recall | 최신 기록을 찾아 이전 판단을 이어간다 | 83.2 → 97.0 | 9 |
| orchestrate | 남은 예산과 체크포인트를 보고 다음 작업을 정한다 | 88.5 → 94.0 | 11 |
| evaluate | 교안·산출물의 오류와 근거를 검증한다 | 86.2 → 94.8 | 11 |
| reflect | 반복 실패의 증거를 검토하고 절차 수정을 제안한다 | 83.2 → 97.0 | 9 |

각 원본 Tier 1 보고서에서 12개 검사가 통과했고, 정적 로딩 예측은 스킬당 6개 호스트 프로필에서 `loads`였다. 5개 모두 전체 평가 증거 상태는 `publication_status: incomplete`다. 저자 미기재, 한계 섹션 제목 패턴, evaluate의 중첩 참조와 JSON 파일 배치, 호스트별 캐시·보조 파일 표시 등은 여전히 보고된다. 확인되지 않은 저자나 라이선스 정보를 추가하지 않았다. JSON 참조와 호스트용 파일은 기존 사용 경로에 보존했다.

원본 Tier 2에 수정한 설명 5개를 넣고 로컬 CPU 임베딩 모델로 비교했다. 5개 모두 색인됐다. 가능한 10쌍 중 유사 경고는 기존 9쌍에서 이번 10쌍으로 늘었다. 가장 가까운 쌍은 recall과 reflect로 0.836이었다. recall 내부의 한 파일은 7조각으로 나뉘었고 중복 경고는 0개였다. 서버 로그에는 임베딩 처리 슬롯 완료 13회, 채팅 처리 0회가 기록됐다. 외부 모델 호출은 없었다. 사용자 요청에 맞는 역할을 실제로 더 잘 고르는지는 미측정이다.

## 2. 프로젝트 제어와 실제 Harbor 준비

| 무엇을 넣었나 | 무엇을 실행했나 | 실제 결과와 해석 |
|---|---|---|
| 사례 파일이 없는 스킬 | 원본 `tier3 validate --strict`와 프로젝트 `check/prepare` | 원본 exit 0이어도 프로젝트는 exit 1. 실패 작업공간을 보존했고 같은 목적지에 있던 파일도 다시 실행할 때 유지됐다. |
| 역할마다 정상 1건, 결함 1건, 다른 역할 1건 | 공개 사례 기본 검사와 명시적 `--pilot` 준비 | 기본 검사는 다섯 역할 모두 exit 1. 기술 시험에서만 15쌍, 총 30작업이 생성됐다. 역할별 3건은 원본의 10개 사례·1개 비호출 기준에 미달하여 모두 `provisional`이다. |
| 같은 자료와 도구, 평가 스킬 유무만 다른 두 작업 | 원본 Harbor 생성기의 `copy_repo=True`, 각 작업의 실제 파일 경로·내용 대조 | evaluate는 공통 파일 35개, 나머지는 각 33개가 두 팔에서 byte 단위로 같았다. 스킬 지침은 처리군에만 있었고 양쪽 모두 문제만 받았다. 정답키와 채점기는 verifier에만 있었다. |
| 15개 공개 사례에 미리 만든 정답 15개와 빈 오답 15개 | **생성된 작업**의 NVIDIA `default_plus_custom` 채점 병합 코드 | 프로젝트 점수는 정답 15건 모두 1, 오답 15건 모두 0. 통제용 기본 점수 0.625와 accuracy 0.75는 30회 모두 그대로였다. 이 숫자는 병합 기능을 검사하기 위해 넣은 값이다. |
| 없는·빈·중복·라벨 불일치 사례, 정상 숫자 4.0, 가짜 숫자 문자열, 중복 JSON 키, 변조된 공통 파일, 오래된 심사 해시 | 프로젝트 회귀와 원본 검사·채점 코드 | 정상 수치 표현은 통과하고 오류 대조는 차단됐다. 별도의 **합성** 10건과 두 명의 가상 식별자로 입력 심사 분기도 확인했다. 실제 독립 평가 사례가 승인됐다는 기록은 없다. |

공통 입력으로 커리큘럼 계약, 실제 [1주차 통합 교안](../lessons/week01/week01_integrated.ipynb)과 [2주차 시간순 전처리 교안](../lessons/week02/week02_temporal_preprocessing.ipynb), 합성 인수인계 기록, 검증 도구와 공개 참고자료를 썼다. 공개 evaluate의 두 문제는 새 배열에서 view·copy·합계의 변화를 구하는 문제와 학습 데이터로만 평균을 구하는 문제다. 공유 자료로 복사한 교안과 학생 교부본 원본 파일은 수정하지 않았다. 준비 과정에서 학생 노트북 셀을 Harbor 안에서 실행하지 않았다.

다섯 지침서에 제시된 예시 명령 8개를 준비된 자료에서 실행했다. 구조가 유효한 옛 그래프가 학습경로 검사에서는 의도대로 실패했고, 별도의 정상 합성 그래프는 통과했다. 공개 예시는 독립 평가에서 제외한다. 설치된 원본 환경에서 저장소 전체 회귀 **280개(기존 271개와 신규 9개)**가 모두 통과했다.

## 3. 다음에 실제 향상을 판정할 방법

새 문제에서 교안 결함을 찾아 올바르게 고치고, 새로운 입력으로 독립 검증까지 마친 과제의 비율을 1차 지표로 삼는다. 동일 사례·자료·모델·채점 기준·예산으로 기존 스킬과 수정 스킬의 짝지은 차이와 불확실성을 보고한다. 정상 교안을 잘못 고친 비율, 놓친 결함, 부적절한 역할 호출, 재개 후 상태 유실·중복, 시간·토큰·비용을 함께 본다. 채택 기준은 기존 오류율과 중요한 회귀의 비용을 측정한 후 미리 정한다.

현재 남은 조건은 학습목표·선수관계·수업 부담을 반영한 주차별 비공개 과제와 독립 심사, 격리 실행기와 에이전트·채점 모델 설정, 예산이 정해진 실제 비교 실행이다. 학생의 학습효과·도움 없는 실제 수행·지연 전이는 이 저장소의 교안 검수 대상에서 제외한다. 학생 자료 수집을 이번 작업의 남은 완료 조건으로 두지 않는다. 새 입력 과제의 조건·정답·설명 검토는 교안 자체를 대상으로 수행한다. 재현 명령, 자료 범위, 결과 해석은 [평가 실행 안내](../tools/skill-evaluation.md)에 있다.

## 4. 검수 범위 정정과 후속 설계

2026-11-18 사용자 지시에 따라 위의 학생 수행 측정 문구를 정정했다. 학생의 실제 학습효과, 진단 응답, 수업 완료 시간과 교사의 실제 노동시간은 이 자동 교안 검수의 대기 과제가 아니다. 없는 관찰을 만들어 넣어서도 안 된다. 과제·선수지식 지원의 설계와 내용·코드의 검증은 유지한다. 실제 학생 효과를 입증했다고 표현하지 않는 것은 결과 해석의 제한이며, 학생 연구를 요구하는 검수 항목이 아니다.

범위 혼합과 내용 편집 연결의 실행 재현 및 구체적 개선안은 [별도 기록](content-review-scope-20261118/README.ko.md)에 있다. 이번 정정은 문서와 진단·설계 기록이다. K01–K16, discovery 및 workflow의 운영 코드는 아직 개편하지 않았다.
