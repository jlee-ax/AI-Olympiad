# 확장·학생 문구 정리의 독립 검토 기준

이전 검토를 읽고 준비한 기준이다. 새 자료의 완료나 학생 학습성과 판정이 아니다. 원본을 수정하지 않으며 최종 경로·SHA를 받은 뒤 검토 폴더 안의 복사본 또는 메모리에서 실행한다.

- 학생용 시간·운영 문구는 분/시수/배정/편성/실측/교사용 진도 조정 등 학습에 불필요한 내부 운영 표현을 찾는다. 문제 자체의 계산·실행·이유 기록 및 Jupyter 사용 방법을 자동으로 제거 대상으로 보지 않는다. 예측 시점·관측 시각·과거/미래·윈도 길이는 학습 개념이므로 보존돼야 한다. 기존 1주 본교안은 이번 변경 범위 밖이라는 부모의 지시를 적용하되 잔여 heading은 관찰로 남긴다.
- 기존 student-plan의 2주 목표는 분할, train-only 전처리 fit, 평균/중앙값, one-hot, 정규화/표준화, 개체·시간순 forward-fill, 원본 분할 후 sliding window·평균·모집단 표준편차, Dummy 검증, CM·accuracy/precision/recall/F1·비상수 점수 ROC, 집단별 집계다. 실제 코드·입력·출력·새 문제를 읽고 설명만 있는 항목과 구별한다.
- 예측 시점의 특성/정답과 원본 ID를 추적한다. 같은 개체 일반화와 미래 예측은 다른 평가 목적이므로 그룹·시간 분리의 의미를 구분한다. 관측 가능한 과거를 검증의 초기 상태로 전달할지 여부는 명시된 계약으로 판정한다. 미래 target이나 다른 집단 값의 유입은 금지한다.
- 평균/중앙값·표준화·MinMax·범주 목록은 훈련에서만 학습하는지 실제 fitted statistics를 읽는다. 검증 값을 극단값·미지 범주로 바꿔도 훈련 통계와 열 의미가 고정되는지 확인한다. Dummy 점수만으로 누수 여부를 판정하지 않는다.
- 범주형 변환은 미지 범주 오류/ignore 정책, all-zero 의미, 훈련·검증 열 수와 순서의 일치를 확인한다. 같은 shape로 검증에 새로 fit해 열 의미가 바뀌는 반례를 넣는다.
- ffill은 개체별이면서 시간순이어야 한다. 첫 관측 전 결측을 미래 관측으로 채우지 않는다. 윈도는 feature/target 원본 ID·시각과 분할을 추적하고, 경계·관측가능성·ddof를 검사한다.
- CM 축/양성 라벨/0분모 정책과 분모를 별도 list/sum/Fraction 구현으로 계산한다. ROC는 비상수 양성 점수, >= 임계값, FPR/TPR, AUC와 hard-label 입력의 차이를 비교한다. 행 정확도와 집단 동일가중 평균을 구분한다.
- 정상본을 새 in-process 커널에서 전부 실행하고 오류 변이를 복사본에만 적용한다. 학생 빈 답안 셀 실행과 실제 작성·독립 성취를 구분한다. 교사용 키와 새 문제의 수치·문구를 대조하되 공개 저장소 파일 분리를 비공개 접근 통제로 취급하지 않는다. 실제 숨은 최종 테스트는 별도 준비·검증 상태를 명시한다.
- 기존2주 수업120분·자습6~8시간의 부담 계획과 확장 범위를 비교하지만 실행초나 도식의 존재로 학생 시간·완수를 보장하지 않는다. 학생본에서 시간 문구를 제거해도 교사용 계획·부담 한계를 숨기지 않았는지 확인한다.

새 반례의 기준 숫자: 중앙값 train[1,3,5,101,NA]=4, mean27.5 / val1001 포함 median5·mean222.2. train[red,blue,red]의 one-hot 열 blue/red에서 val[green,blue]의 ignore 결과[[0,0],[1,0]], 검증에 별도 fit하면 같은shape의 blue/green 열[[0,1],[1,0]]. train[0,2,4] mean2·var8/3에서 val6의 z=√6. train[[1,2],[3,4]]에서 val[5,6]의 Standard[3,3], MinMax[2,2], 행L2=[5/√61,6/√61].

시계열 반례: (A,1,10),(B,1,NA),(A,2,NA),(B,2,80)의 정상 ffill은 A2=10·B1=NA, 전체 ffill은 B1=10으로 개체 누수. 입력순(A,3,30),(A,1,NA),(A,2,10)에 시간정렬 없는 ffill은 A1=30으로 미래 누수. t1~6 값[1,3,5,7,9,11]을 t1~3/t4~6 원본 블록으로 나누고 과거2개→다음값을 만들면 엄격한 블록 계약에서 train[1,3]→5·val[7,9]→11만 가능하다. 다른 과거상태 전달 계약은 따로 판정한다.

ROC 기준: truth[0,1,0,1]·scores[.1,.35,.4,.8]의 점은 (0,0),(0,.5),(.5,.5),(.5,1),(1,1), AUC3/4. threshold .4 hard-label 입력은 AUC1/2, 반대 클래스 점수는 AUC1/4. 이는 실제 새 교안의 입력이 아니라 오류 감지용 별도 합성 반례다.
