# 설계 및 반복 절차 (논의용)

## 목적과 범위

후속 에이전트가 요청, 수행, 산출물, 근거, 의존성, 검토 및 미결정을 구별하여 이어서 작업할 수 있도록 한다. KOAI 2027 중학생(코딩 기초 있음), 10주 × 2시간 수업을 가정한다. 공식 대회 범위, 학생 진단, 실제 수업 설계는 별도 확인이 필요하다. 이 저장소는 기초 설계일 뿐 자동 교육 시스템이 아니다.

## 그래프와 기록

- 노드 유형: request(요청), skill(스킬), artifact(산출물), evidence(근거), decision(결정), review(검토). 각 노드는 고유 ID와 상태를 갖는다.
- 간선은 `from`, `to`, `type`을 명시한다. `depends_on`은 전자가 후자를 필요로 한다. `supports`는 전자가 후자를 뒷받침한다. `revises`는 전자가 후자를 수정·대체함을 기록한다. `informs`는 비차단 참고 관계다.
- 반복 검토와 피드백의 순환은 허용한다. 다만 `depends_on` 순환은 대기 상태가 교착될 수 있으므로 경고하고, 실제 수행 전 분해 또는 명시적 해결을 요구한다. 검증 도구는 어떤 순환도 자동 삭제하거나 바꾸지 않는다.
- 출처, 가정, 버전, 변경 이유, 판단 근거, 남은 불확실성을 연결한다. '요청됨', '완료됨', '검증됨'을 혼동하지 않는다. 실제 사실처럼 보이도록 가상의 기록을 쓰지 않는다.
- 민감한 학습자 데이터나 비밀은 저장소에 넣지 않는다. 저장소 비공개 여부는 별도 확인한다.

## 30분 검토 단위 (사용자가 요청한 간격)

검토 간격은 사용자가 요청한 30분으로 한다. 이는 효능이 입증된 최적 시간이라는 뜻은 아니다. 평가 기준과 개선 효과는 사용자와 논의하고 검증한다. 외부 타이머, 스케줄, 반복 실행을 여기서 만들거나 시작하지 않는다.

1. 시작: 범위와 입력 버전, 변경 요청, 허용된 행동, 의존성 및 종료 조건을 기록한다.
2. 수행: 한정된 변경을 작업하고 주장과 근거를 연결한다. 외부 조치에는 별도 권한과 확인 규칙을 적용한다.
3. 검증: 바뀐 노드와 그 영향을 받는 하위 의존 노드를 확인한다. 범위 밖 전체 재검증을 생략할 때 이유와 잔여 위험을 남긴다. 의존 그래프만으로 영향이 완전히 포착되었다고 가정하지 않는다.
4. 결정: continue(다음 단위 제안), pause(사용자 결정 대기), stop(완료·예산 소진·반복 정체·권한/안전 문제), blocked(진행 장애)를 기록한다. 한 번의 `continue`는 다음 자동 실행 권한이 아니다.
5. 인계: 이전 결정과 근거를 유지하고, 변경된 증거나 요구가 있을 때만 재검토한다. 이미 해결한 문제를 반복적으로 뒤집지 않도록 이유를 적는다. 오류가 발견되면 이전 기록을 조용히 덮지 않고 수정 근거를 추가한다.

## 후보 평가 기준 (가중치와 임계치 미확정)

- 정확성: 주장과 출처의 일치, 공식 범위와의 일치, 사실 검증.
- 교육 적합성: 학생의 선행 지식·부담·시간과의 적합성, 학습 목표와 평가의 연결.
- 추적 가능성: 요청→작업→산출물→근거→검토가 연결되는지.
- 변화의 정당성: 새 증거 또는 요구에 근거한 개선인지, 이전 결정과 충돌하면 이유가 명시되는지.
- 실행 가능성 및 안전: 의존성, 권한, 개인정보, 시간·도구 제약.

숫자 점수, 통과 기준 및 반복 정체 판정 횟수는 사용자와 합의하기 전 미정이다. 검토 간격은 사용자가 요청한 30분이다. 검증 실패와 미실행 검증은 별도 표시한다.

## 기록 보존과 검토 범위

검토 범위를 좁히거나 낡은 항목을 보관 처리하는 것은 영구 삭제와 다르다. 원기록은 수정 이력을 남기고 보존한다. 어떤 기록을 얼마나 보존할지, 언제 삭제할지는 추후 협의하며 영구 삭제를 자동으로 수행하지 않는다. Git에 기록한 민감정보는 일반적인 파일 삭제만으로 이력에서 없어지지 않을 수 있으므로 처음부터 올리지 않는다.

## 관련 기존 작업

사용자 계정의 공개 저장소 [Evidence-Gated Loop](https://github.com/jlee-ax/evidence-gated-loop-skill)는 기준선 고정, 검토 지적사항 기록 및 현재 증거에 근거한 종료를 다룬다. 본 프로젝트와 겹치는 부분을 추후 비교하되, 기존 절차를 이 프로젝트의 승인된 기준으로 간주하거나 자동 설치·실행하지 않는다. 본 프로젝트의 보류·중단·검토 범위는 사용자와 별도로 합의한다.
