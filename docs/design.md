# pstack 기반 KOAI 1–2주차 제작 절차 설계

현재 단계는 **제작 절차·검증 도구·기록 방식의 구현**이다. 실제 수업 자료 제작, 학습자 실험, 반복 실행 및 스케줄 등록은 시작하지 않는다. 평가 기준의 합의 여부는 미설정이며, 수업 제작과 반복 실행은 비활성 상태로 둔다. 이 문서의 제안은 사용자 합의나 학습 효과의 증거를 대신하지 않는다.

## pstack을 중심에 두는 이유와 적용 범위

Lauren Tan(@poteto)의 [pstack](https://github.com/cursor/plugins/tree/c742dd61706fbacc1b95f1a20b7b988cf096ce6c/pstack)을 작업 운영의 출발점으로 삼는다. 문제 파악, 역할 분리, 검증 가능한 작은 변경, 근거에 따른 유지·되돌리기, 수정 이력과 인계를 보존한다. 교육 연구는 이 운영 방식을 대체하는 별도 구조가 아니라 **무엇을 개선으로 인정할지**를 보충한다.

| pstack의 원래 절차 | 이 프로젝트에서 유지할 부분 | 교육 자료에 맞게 바꿀 부분 |
|---|---|---|
| [`orchestrate`](https://github.com/cursor/plugins/blob/c742dd61706fbacc1b95f1a20b7b988cf096ce6c/pstack/skills/poteto-mode/playbooks/orchestrate.md) | 조정자·작업 소유자·독립 검증자 분리, 먼저 한 단위를 검증한 뒤 확장 | 목표·선수지식·수업시간을 확인하고, 학생용 자료와 교사용 검증 자료를 함께 관리 |
| [hillclimb](https://github.com/cursor/plugins/blob/c742dd61706fbacc1b95f1a20b7b988cf096ce6c/pstack/skills/poteto-mode/playbooks/hillclimb.md) | 기준선 고정, 가설 하나와 변경 하나, 측정 후 유지·되돌리기 | 정확성·교사 검토시간·교육 적합성을 구별하고, 평가 점수 상승을 학습 향상으로 해석하지 않음 |
| [eval](https://github.com/cursor/plugins/blob/c742dd61706fbacc1b95f1a20b7b988cf096ce6c/pstack/skills/poteto-mode/playbooks/eval.md) | 동일 조건의 후보 비교, 작성자 정보를 가린 검토 | 학습 목표는 공개하되 비교 후보 이름·모델·미공개 평가 항목은 분리; 실제 교사 판정과 자동 판정의 불일치 기록 |
| [`correct`](https://github.com/cursor/plugins/blob/c742dd61706fbacc1b95f1a20b7b988cf096ce6c/pstack/skills/correct/SKILL.md) | 반복 오류를 묶고 구조·타입·검사로 예방; 실제 과거 오류를 검사가 잡는지 증명 | 기계로 확인할 오류와 교육적 판단을 분리; 정정 근거, 대체 대상, 영향받은 자료·검사를 연결 |
| [`reflect`](https://github.com/cursor/plugins/blob/c742dd61706fbacc1b95f1a20b7b988cf096ce6c/pstack/skills/reflect/SKILL.md) | 수용·거절·보류를 구별하고 반복 교훈을 구조적 예방으로 연결 | 관찰된 결과와 추측을 구별; 스킬 변경은 후보로 기록하고 다음 비교에서 검증 |

검토한 원본은 `c742dd61706fbacc1b95f1a20b7b988cf096ce6c`(2026-10-27)이며, 상세한 원본–로컬 대응은 [pstack 추적 문서](pstack-traceability.md)에 기록한다. 향후 실행에서는 실제 읽은 원본·로컬 스킬의 리비전과 해시를 남긴다. 이 문서는 pstack 설치나 원본 스킬의 무제한 실행을 지시하지 않는다. 특히 간결한 코드와 간결한 학습 설명은 같은 목표가 아니다. 초심자에게 필요한 설명을 자동 삭제하지 않는다.

## 확인된 대회 기준과 미합의된 수업 범위

2026-11-10에 확인한 [KOAI 2027 공고](https://kitpa.org/notice/89)의 [대회요강](https://kitpa.org/storage/6df0e67a-48d7-4255-ba4f-7d86b2bd2824.pdf)은 중등부·고등부 모두 1–4과목 전범위를 명시한다(7쪽 §11). 두 부문 모두 필기 3시간(선택형 80문항, 서술형 10문항)과 코딩 3시간(2문항)이다(8쪽 §12). [2027 안내 페이지](https://kitpa.org/koai/2027)의 상세 내용도 일치한다. 중등부 일정 제목에서 코딩이 빠진 것은 상세 설명과 요강을 함께 읽어 해석한다.

연결된 [실라버스](https://kitpa.org/koai/syllabus)는 여전히 `IOAI 2026 기준`으로 표시되어 있다. 현재 2027 요강이 참조하는 범위라는 점과 표시된 버전을 함께 기록한다. [2026 예시문항 공고](https://kitpa.org/files/36)의 중등부 1–2과목 제한을 2027 규칙으로 가져오지 않는다. 예시문항에는 공개된 공식 정답이 없으므로 에이전트 풀이를 공식 정답으로 표시하지 않는다.

| 항목 | 현재 성격 | 제작 전에 필요한 결정 |
|---|---|---|
| KOAI 2027 중등부, 코딩 기초가 있는 학생, 10주 × 2시간 | 기존 저장소의 초안 대상 | 실제 대상·선수지식·총 수업시간 확인 |
| 1주차 Python / CSV / NumPy | 기존 초안의 주제 후보 | 관찰 가능한 목표, 필요한 선수지식, 포함·제외 범위 |
| 2주차 데이터 분할 / 전처리 / 평가 지표 | 기존 초안의 주제 후보 | 1주차와의 연결, 이해·구현·설명 중 요구 수준 |
| 주당 학습량 | 기존 기록에 240분 수업, 120분 수업 및 서로 다른 과제시간이 혼재 | 수업·실습·과제·복습 시간을 각각 합의 |

공식 출제 범위는 학습 목표의 출처가 될 수 있지만, 모든 주제를 20시간에 익힐 수 있다는 증거는 아니다. 위 표의 주제는 확정 교육과정이나 이번에 제작한 수업 자료가 아니다.

## 제작 단위의 계약

향후 승인된 1–2주차 제작은 주차별 자료 묶음을 대상으로 한다. 묶음의 구성 제안은 목표·선수지식 설명, 학생용 설명과 실습, 교사용 지도·예상 오개념·풀이, 실행 가능한 코드 및 데이터 명세, 평가 항목과 채점 근거, 변경 및 검토 기록이다. 지금은 해당 내용을 생성하지 않는다.

각 작업에는 다음 연결을 요구한다.

1. **요청 → 목표:** 사용자가 허용한 범위, 현재 대회 원문 위치, 학습자가 보여야 할 행동, 필요한 선수지식. 공식 출처에서 직접 온 내용과 교사의 교육적 선택을 구별한다.
2. **목표 → 자료·평가:** 자료의 어느 부분이 목표를 다루고 어떤 관찰로 달성을 판단할지 연결한다. 내용 언급만으로 목표를 달성했다고 표시하지 않는다.
3. **변경 → 가설:** 현재 문제, 기준선, 제안 변경, 기대되는 관찰, 반증 조건, 영향 범위. 단순 문체 수정에도 필요한 이유를 남긴다.
4. **검토 → 정확한 대상:** 검토한 자료 리비전·내용 해시와 입력, 스킬, 기준, 평가기, 참고자료의 버전을 연결한다.
5. **결정 → 증거:** 유지·되돌리기·추가 검토·변경 없음의 이유, 실행한 검사와 미실행 검사, 남은 이견을 기록한다.

구체적인 기계 판독 필드와 명령은 [workflow 계약](workflow-contract.md)을 따른다. 이 문서는 별도 스키마를 정의하지 않는다.

## 역할과 판단 책임

- **조정자:** 허용 범위와 입력 버전을 확정하고 작업을 분해한다. 작성자·검토자 결과를 대조하며 미결정을 보존한다.
- **작성자:** 하나의 가설에 해당하는 변경을 만들고 근거와 의도한 효과를 설명한다. 자신의 자료에 최종 승인 판정을 내리지 않는다.
- **검토자:** 작성자와 다른 에이전트 실행 또는 사람으로 배정한다. 자료·독립 참고근거·평가 기준을 직접 확인하며 작성자의 성공 주장만으로 통과시키지 않는다. 모델이 다르다는 사실 자체는 독립적인 정답 근거가 아니다.
- **교사 또는 교육 검토자:** 목표·부담·오개념·설명 적합성과 평가 해석을 검토할 역할이다. 모든 사소한 수정마다 사람의 승인을 요구하는 규칙을 만드는 것은 아니다. 구체적인 참여 시점과 표본 수는 미합의다.

자동 검사는 링크·구조·해시·실행 결과를 확인할 수 있다. 이 검사가 교육적 적합성이나 학생의 숙련을 인증하지는 않는다. 사람의 검토도 불일치가 있을 수 있으므로 이견과 판정 근거를 남긴다.

## 한 번의 작업과 30분 체크포인트

현재 구현하는 것은 수동으로 요청할 수 있는 읽기 전용 `validate`, `decide`, `fingerprint`, `recall` 동작이다. 이 도구가 수업 자료를 생성하거나 수정하고, 외부 서비스를 호출하거나, 다음 실행을 예약하지 않는다. `fingerprint`는 기록된 상태에서 문맥·기준·예산의 지문을 계산하며 실제 파일의 정확성이나 실행 완료를 증명하지 않는다. 실제 명령 형식은 workflow 계약을 따른다.

향후 제작이 승인된 경우의 절차는 다음과 같다.

1. **Recall / ground:** 최신 요청과 결정, 정정·대체 관계, 관련 출처와 실제 입력을 확인한다. 과거 기록의 제안을 현재 권한으로 승격하지 않는다.
2. **Orchestrate:** 허용된 작업과 예산 안에서 기준선을 정하고, 검증할 가설이 있을 때만 작성 작업을 위임한다.
3. **Eval / hillclimb:** 독립 검토와 해당 검사를 수행한다. 미실행·실패·이견을 숨기지 않고 기준선과 비교한다. 판단 기준이 미합의라면 개선을 확정하지 않는다.
4. **Correct:** 확인된 오류를 정정하고 영향받은 자료와 검사를 다시 확인한다. 반복 가능한 오류에는 예방 검사를 제안하고, 그 검사가 알려진 오류를 잡으면서 올바른 사례를 잘못 거절하지 않는지 확인한다. 오류가 없다는 이유만으로 새로운 변경을 요구하지 않는다.
5. **Reflect / handoff:** 관찰된 결과, 거절한 변경, 불확실성, 다음에 확인할 사항을 남긴다. 다음 주기의 실행 권한은 별도로 판단한다.

사용자가 제시한 **30분은 깨우기·점검·인계 간격**이다. 매 30분마다 변경·커밋·PR을 만들어야 한다는 뜻이 아니며, 학습에 최적이라는 연구 결과도 아니다. 실행 중이라면 일관된 기록을 남길 수 있는 지점에서 점검한다. 진행 중인 검사를 강제 종료하거나 미완료 작업을 성공 처리하지 않는다. 현재 결정 도구의 체크포인트 도달 결과는 검토를 위한 `pause`이며 스케줄러가 아니다. `continue` 판정도 반복 실행·제작 권한을 새로 부여하지 않는다.

## 최신 증거와 완료의 의미

자료가 바뀌면 이전 검토를 새 자료에 자동 적용하지 않는다. 참고자료, 평가 기준, 평가기 또는 스킬의 관련 버전이 바뀐 경우에도 연결된 검토의 유효성을 다시 판단한다. 대상 자료와 평가 문맥이 일치하지 않는 증거는 오래된 기록으로 보존하고 현재 완료의 근거로 사용하지 않는다. 의존 그래프가 빠진 관계까지 모두 포착한다고 가정하지 않는다.

검사 결과는 실제 관찰에 따라 통과·실패·미실행 등으로 구별한다. 목표 완료 표시는 합의된 필수 검사가 모두 **현재 대상과 문맥**에 대해 충족되어야만 가능하다. 합의가 없거나 필수 증거가 누락되면 완료가 아니다.

**자료의 검토 상태와 학습자의 숙련 상태는 별개다.** 코드 실행이나 교사 검토가 끝나도 실제 학습자 평가가 없다면 숙련은 `untested`로 남는다. 현재 저장소에는 이 절차로 관찰한 학습 성과나 실제 평가 점수가 없다.

검사와 비교 실험은 [평가 프로토콜](evaluation-protocol.md), 합의 항목과 현재 권한은 [결정 문서](decisions.md)를 따른다.
