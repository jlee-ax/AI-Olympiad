# 평가 프로토콜: 자료 개선과 학습 성과 구별하기

이 문서는 향후 1–2주차 자료 제작을 검증하기 위한 **실행 가능한 검사 계약과 비교 실험 제안**이다. 수업 내용·문제·풀이를 생성하지 않으며, 실제 검토 점수나 학습자 결과를 포함하지 않는다. 현재 통과 임계치, 실험 예산, 표본 수, 개선 정체 횟수는 미합의다. 기계 판독 표현은 [workflow 계약](workflow-contract.md)이 기준이다.

## 증거의 네 층

| 층 | 확인하는 주장 | 통과해도 확인되지 않는 주장 |
|---|---|---|
| 기록·추적 | 참조가 존재하고 대상 리비전·해시·평가 문맥이 일치함 | 출처가 내용상 옳거나 목표가 적절함 |
| 기술·내용 | 코드가 해당 환경에서 실행되고 확인된 사실·풀이와 일치함 | 학생이 이해하거나 다른 상황에 적용할 수 있음 |
| 교육 적합성 | 목표·선수지식·설명·연습·평가·시간이 해당 학습자에게 적절하다는 검토 근거 | 실제 학습 효과, 장기 기억 또는 전이 |
| 학습 성과 | 실제 학습자가 조건에 맞는 평가에서 보인 수행 | 다른 학생·주제·기간으로의 자동 일반화 |

현재 마지막 층의 상태는 **`untested`**다. 자동 검증 결과나 에이전트의 학생 역할 시뮬레이션을 학습자 데이터로 기록하지 않는다.

## 검사 목록과 관찰 방법

아래 검사들은 제작 후 무엇을 확인할지에 대한 제안이다. 실제 실행에서는 각 검사에 검사자, 대상 자료 해시, 입력·스킬·기준·평가기·참고자료 버전, 수행 시각, 관찰 결과와 증거 위치를 연결한다. 필수 여부와 수치 판정은 합의 이후 설정한다.

| 검사 | 구체적인 확인 | 실패 또는 미검증으로 남기는 경우 |
|---|---|---|
| 권한·범위 | 허용된 요청과 자료·목표·주차의 연결 확인 | 제작 권한 없음, 미합의 대상을 확정한 것으로 취급 |
| 목표·출처 | 각 핵심 목표·주장을 원문 위치와 연결하고 공식 규칙/교육적 선택을 구분 | 2026 중등부 제한을 2027에 적용, 없는 공식 정답 인용, 출처로 뒷받침되지 않는 주장 |
| 최신성 | 대상 리비전·해시와 전체 평가 문맥이 검토 기록과 일치하는지 확인 | 내용·참고자료·평가기 등이 바뀌었는데 이전 통과를 재사용 |
| 재현 실행 | 선언된 의존성과 데이터로 새 실행 환경에서 코드·노트북을 순서대로 실행; 종료 상태와 출력 확인 | 숨은 셀 상태·미제공 파일·미설치 의존성에 의존, 실제 실행을 하지 않음 |
| 내용·정답 | 풀이와 결과를 독립 참고자료·수동 계산·별도 구현 등 적절한 방법으로 확인 | 생성한 풀이를 같은 생성물의 정답 근거로만 사용, 복수 정답·모호한 조건 미해결 |
| 데이터·평가 절차 | 분할·전처리·지표 계산이 명시된 목적과 일치하는지 확인 | 평가 데이터 정보가 학습에 섞임, 분모·라벨·지표 해석 불일치 |
| 목표와 평가의 연결 | 각 평가 항목이 어떤 행동의 증거인지 설명; 답 암기·실행 성공과 설명·전이를 구별 | 목표는 적용인데 평가가 용어 재인에만 의존, 제공한 답 복사로 완료 가능 |
| 선수지식·설명 | 필요한 개념을 먼저 제공하거나 전제로 명시; 예시 단계·설명·연습 사이 연결 확인 | 학생 수준이 미확인인데 난이도 적합을 단정, 핵심 추론 단계를 설명 없이 생략 |
| 부담·사용성 | 수업·실습·과제·복습 시간 별도 합산, 자료·화면·출력의 실제 가독성 검토 | 서로 다른 시간표 혼용, 보이지 않는 수식/출력, 예상 시간을 관찰된 시간으로 보고 |
| 회귀·완결성 | 변경 자료와 영향받는 풀이·평가·참고자료 연결을 다시 확인 | 설명만 수정하고 풀이·코드는 이전 상태, 영향 범위를 조사하지 않음 |

직렬화하는 `check.status` 값은 `passed`(통과), `failed`(실패), `not_run`(미실행) 세 가지뿐이다. “해당 없음”은 사람이 남기는 사유 또는 검사 제외 제안이며 별도 상태값이 아니다. 필수 검사에 대한 면제나 통과로 사용할 수 없고, 수행하지 않은 필수 검사는 `not_run`으로 남긴다. `required_checks`를 바꾸려면 평가 기준의 합의를 갱신하고 고정한 기준선도 새 리비전으로 설정한 뒤, 변경된 문맥에 맞는 검토 증거를 다시 확보한다. 필수 검사가 빠지거나 오래된 증거에 의존하면 완료를 판정하지 않는다. 증거가 없는 칸에 0점이나 통과를 대신 넣지 않는다.

## 교육 적합성 검토 기준

처음에는 가중 합산 점수보다 **관찰·근거·이견·미검증 사유**를 기록한다. 숫자 척도를 도입한다면 각 수준의 의미와 예시를 별도로 합의하고 평가자를 교정한다.

| 차원 | 검토자가 답할 질문 | 필요한 근거 |
|---|---|---|
| 정확성과 목표 일치 | 설명·코드·풀이가 맞으며 합의된 목표를 실제로 다루는가? | 독립 확인 결과, 목표–자료–평가 연결 |
| 선수지식과 설명의 양 | 요구되는 선행 지식이 확인되었으며 설명을 줄이거나 늘린 이유가 있는가? | 대상 진단 또는 명시된 가정, 단계별 설명 검토 |
| 학습자 활동 | 학생이 무엇을 회상·설명·구현·비교해야 하는가? | 활동 요구와 피드백 설계; 정답 제공 시점 |
| 평가 해석 | 성공이 어떤 능력을 보여 주며 무엇은 보여 주지 못하는가? | 채점 근거, 독립 풀이, 예상 오개념 및 모호성 검토 |
| 실행 가능성과 부담 | 합의된 시간·도구·자료 접근 조건에서 사용할 수 있는가? | 실제 실행 기록, 교사 검토, 추정과 관찰을 구별한 시간표 |

학습 목표·활동·평가의 연결은 [Biggs(1996)](https://doi.org/10.1007/BF00138871)의 설계 틀을 참고한다. 이를 이 에이전트 구조의 효과를 증명한 실험으로 표현하지 않는다. [Karpicke와 Blunt(2011)](https://learninglab.psych.purdue.edu/downloads/2011/2011_Karpicke_Blunt_Science.pdf)의 과학 글 회상 실험은 지연 평가를 포함할 근거를, [Chen 등(2015)](https://repository.lboro.ac.uk/articles/journal_contribution/The_worked_example_effect_the_generation_effect_and_element_interactivity/12053721)의 연구는 선수지식·복잡도에 따라 설명과 독립 해결의 효과가 달라질 수 있음을 뒷받침한다. 어느 연구도 KOAI 수업에 대한 동일한 효과나 30분 작업 주기의 효능을 입증하지 않는다.

## 평가기 자체의 검증: 틀린 사례와 맞는 사례

검토기는 우선 실제 오류를 발견하고 맞는 자료를 불필요하게 고치지 않는지 확인해야 한다. 이 단계에서 만드는 도구 테스트용 기록은 **합성 메타데이터**라고 표시하며 실제 수업 검토나 학생 수행으로 기록하지 않는다.

향후 자료 검토기 평가에는 다음 구성을 제안한다.

1. 독립적으로 확인한 올바른 사례와, 위치·원인이 확인된 오류 사례를 준비한다. 현재는 수업용 사례 내용을 제작하지 않는다. 오류 유형은 틀린 정답, 계산·실행 오류, 평가 데이터 누출, 연도·범위 혼동, 모호한 문항, 부적절한 선수지식 가정 등으로 분리한다.
2. 오류의 위치·기준 답·심각도는 작성자에게 공개하지 않은 평가용 기록으로 관리한다. 의심만 있는 사례는 확정 정답 집합에 넣지 않고 별도 이견 사례로 둔다.
3. 맞음/틀림 라벨뿐 아니라 원인과 위치를 찾아낸 증거를 요구한다. 알려진 오류를 놓친 비율과 올바른 사례를 잘못 거절한 비율을 각각 측정한다.
4. 표현 순서와 작성자 표식을 바꾸어 판정이 흔들리는지 확인한다. 평가자 간 이견은 숨기지 않고 독립 근거로 해결하거나 미해결로 남긴다.
5. 평가기·프롬프트를 수정할 때 사용한 사례와 최종 확인용 사례를 분리한다. 같은 사례에 맞춘 점수만으로 일반 성능을 주장하지 않는다.

**구분:** 실패 상태의 합성 기록을 도구가 차단하는 테스트는 결정 로직의 검증이다. 실제 틀린 풀이를 평가기가 발견하는지는 별개의 내용 검증이다. 전자의 성공을 후자의 성공으로 보고하지 않는다.

Oak의 [Aila 자동 평가 사례 연구(2025)](https://arxiv.org/pdf/2502.10410)는 전문가 피드백 이후 판정 일치가 개선되었지만, 하나의 문항 품질 기준과 제한된 사람 평가를 다뤘다. 이는 교정과 별도 검증의 근거이며 자동 승인기의 완성도를 증명하지 않는다.

## 비교 실험: pstack의 어느 부분이 도움이 되는가

아래는 합의 후 수행할 실험 제안이다. 실제 자료를 만드는 실험도 제작에 해당하므로 현재는 실행하지 않는다.

| 후보 | 공통 pstack 기반 | 바뀌는 요소 | 검증할 질문 |
|---|---|---|---|
| A: 강한 단회 기준선 | 동일한 목표·출처 조사·작성자/검토자 분리·결과 기록 | 첫 작성과 한 번의 독립 검토 후 종료 | 반복 없이 얻는 품질과 총 비용은? |
| B: 제한된 반복 | A와 동일 | pstack hillclimb의 가설·측정·유지/되돌리기를 합의된 예산 내 추가 | 반복이 실제 오류·교사 수정시간을 줄이는가? |
| C: 교육 기준 보강 반복 | B와 동일 | 목표–평가 연결, 선수지식·부담, 교정된 교육 검토 기준 추가 | 교육 보강의 이익이 추가 검토비용을 상쇄하는가? |

모든 후보에 같은 초기 자료·출처 묶음·요청·학습 목표·모델 버전·도구 접근을 제공한다. 후보별 총 토큰·비용·경과시간·도구 호출·교사 투입시간을 기록한다. 호출 횟수가 다른 후보도 총 자원 예산이 같도록 설계하거나, 같지 않으면 품질–비용 관계로 보고한다. 예산 값과 반복 수는 합의 전 미설정이다. 단회 기준선에도 완전한 작업 설명을 제공해 반복 후보에만 유리한 정보를 주지 않는다.

평가자는 후보·모델 이름을 가린 결과를 같은 기준으로 검토하며 제시 순서를 바꾼다. 기준을 만든 자료와 최종 확인 자료는 분리한다. 한 번의 성공이나 가장 좋은 실행만 보고하지 않고 실행 실패·거절한 변경·회귀·변경 없음도 포함한다. 비교 중 목표나 기준을 바꿨다면 기존 비교와 분리해 새 기준선을 설정한다.

30분 점검 요구는 모든 후보에 동일하게 적용한다. 점검 횟수나 변경량을 품질 점수로 사용하지 않는다. 새 근거가 없을 때 변경하지 않은 후보도 유효한 결과다.

## 측정 항목과 미합의 값

| 지표 | 기록 방법 | 현재 상태 |
|---|---|---|
| 교사 총 소요시간 | 작성 지원·검토·수정·수업 직전 보완을 구분해 합산; 실측/자기보고/추정을 표시 | 측정 설계만 있음; 값·목표 미설정 |
| 확인된 오류 | 기준선/수정본에서 독립 확인한 오류 수, 심각도, 검사 대상 수와 분모 | 실제 관찰 없음; 허용 수준 미합의 |
| 평가기 거짓 통과·거짓 거절 | 알려진 오류 중 놓친 수 / 오류 사례 수, 맞는 사례 중 잘못 거절한 수 / 맞는 사례 수 | 사례·표본 수·허용 비율 미합의 |
| 검토 일치와 이견 | 항목별 판정·근거·판정자 차이; 정답 불확실성 별도 기록 | 실제 관찰 없음 |
| 반복의 순이익 | 확인된 결함 감소와 새 결함, 교사 시간, 전체 비용을 함께 비교 | 최소 개선폭·정체 판정 미합의 |
| 학습 성과 | 승인된 별도 연구에서만 독립 수행·지연 기억·새 문제 전이를 측정 | `untested`; 현재 수집·실험 안 함 |

[EEF/NFER의 ChatGPT 수업 준비 실험](https://educationendowmentfoundation.org.uk/projects-and-evaluation/projects/choices-in-edtech-using-generative-ai-chatgpt-for-ks3-science-lesson-preparation-2024-teacher-choices-trial)과 [Aila 평가](https://educationendowmentfoundation.org.uk/projects-and-evaluation/projects/aila-teacher-choices-trial)는 준비시간과 자료 품질을 구별해 평가했다. 이 프로젝트도 교사 시간 절약, 자료 결함 감소, 학습 향상을 서로 다른 결과로 보고한다. 기존 연구의 수치를 이 프로젝트의 목표값이나 성과로 복사하지 않는다.

## 판정과 종료

현재 기준 합의가 없으므로 자료의 개선 확정·제작 개시·반복 실행을 제안서만으로 허용하지 않는다. 향후 합의 후에도 현재 대상과 평가 문맥에 맞는 필수 검사가 모두 있어야 목표 완료를 검토할 수 있다. 알려진 실패, 오래된 검토, 누락된 근거 또는 해결되지 않은 필수 이견을 좋은 평균 점수로 상쇄하지 않는다.

30분 체크포인트는 검토를 위한 일시정지이며, 다음 실행을 예약하지 않는다. 총 예산 소진·권한 부족·필수 의존성 장애·합의된 정체 조건에 따른 중단 사유는 분리한다. 정체 횟수나 최소 개선폭은 임의로 채우지 않는다. 최종 보고에는 무엇이 확인되었는지, 무엇이 실패·미실행·미검증인지, 어떤 결정이 남았는지를 함께 적는다.
