# 결정 상태와 다음 합의

이 문서는 승인된 작업과 제안을 분리한다. 사용자가 이번에 허용한 것은 **pstack을 중심으로 한 다음 설계와 구현**이다. 이 승인을 수업 자료 제작이나 반복 실행 승인으로 넓히지 않는다. 현재 기계 판독 상태의 기준 합의는 미설정이며 제작·반복 실행은 비활성이다.

| 항목 | 현재 상태 | 이 단계에서 할 수 있는 일 / 다음 조건 |
|---|---|---|
| 설계 문서, 스킬 계약, 읽기 전용 검증·결정·검색 도구 | 사용자 허용 범위 | 구현·검토·테스트 가능. 실제 자료나 가상의 학습 결과를 만들지 않음 |
| 1–2주차 수업 자료 제작 | 보류 | 대상·목표·학습량·필수 검사·판정 기준을 구체화하고 사용자가 합의한 뒤 별도 제작 권한 확인 |
| 30분마다 반복 실행 및 스케줄 등록 | 보류 | 30분은 점검 간격에 대한 요구. 반복 권한·실행 환경·예산·중단 조건이 합의되기 전 등록·실행하지 않음 |
| 병합·배포·게시 | 이 설계 승인에 포함되지 않음 | 해당 대상과 작업에 대한 명시적 권한 필요. 로컬 검증 성공을 외부 변경 승인으로 해석하지 않음 |
| 교육적 통과 임계치·가중치·정체 기준 | 미합의 | 제안과 판정 근거를 검토하고 실제 값을 합의. 임의의 숫자·가짜 점수로 채우지 않음 |

## 확인된 사실

- 설계의 중심은 Lauren Tan(@poteto)의 pstack이며, `orchestrate / hillclimb / eval / correct / reflect`의 역할을 [설계 문서](design.md)에 대응시킨다.
- [KOAI 2027 공식 대회요강](https://kitpa.org/storage/6df0e67a-48d7-4255-ba4f-7d86b2bd2824.pdf)은 중·고등부 모두 1–4과목과 필기·코딩을 명시한다. [실라버스](https://kitpa.org/koai/syllabus)는 아직 `IOAI 2026 기준` 표기다. 2026의 중등부 범위 제한을 2027에 적용하지 않는다.
- 검토한 자료·문맥의 버전이 바뀌면 과거 통과 기록만으로 현재 목표를 완료 처리하지 않는다.
- 자료 검토와 학습 성과는 별개다. 현재 학습자 숙련은 미검증이며 실제 수업·학생 실험을 수행하지 않았다.

이 확인 사실은 아래 교육과정 선택에 대한 사용자 합의를 대신하지 않는다.

## 제작 전에 결정할 항목

| 결정 | 현재 제안 또는 확인할 선택 | 합의 때 남길 내용 |
|---|---|---|
| 대상과 전제 | 기존 초안은 KOAI 2027 중등부·코딩 기초 있음·10주 × 2시간 | 실제 대상, Python·수학·통계 선수지식, 진단 방식 |
| 1–2주차 목표 | 기존 1주차 Python/CSV/NumPy, 2주차 분할/전처리/지표는 후보 | 각 목표의 행동, 필요한 근거, 포함·제외 내용, 대회 범위와의 관계 |
| 학습량 | 기존 기록의 수업·과제·복습 시간이 서로 다름 | 주당 수업·실습·과제·복습의 각 한도와 총합. 20시간으로 전범위 숙련을 가정하지 않음 |
| 산출물 묶음 | 학생용 설명·실습, 교사용 풀이·지도, 코드·데이터, 평가·검토 기록 | 실제 필요한 구성, 형식, 사용 환경 및 배포 대상 |
| 필수 검사와 판정 | [평가 프로토콜](evaluation-protocol.md)의 구조·출처·실행·정답·교육 적합성 검사 | 필수·선택 항목, 담당자, 오류 심각도, 재검토 조건; 필수 목록 변경 시 기준 합의와 기준선 리비전 갱신 |
| 수치 기준 | 오류율·거짓 통과율·교사 시간·자료 품질 비교 후보 | 분모, 측정 방법, 표본 수, 허용 오차, 최소 개선폭. 합의 전 값은 미설정 |
| 사람의 역할 | 독립 교육 검토와 이견 해결은 필요; 참여 빈도는 미정 | 최초 기준 설정·표본 검토·예외 판단 중 실제 참여 시점과 담당자 |
| 비교 실험 | 단회 pstack / 반복 pstack / 교육 기준 보강 pstack | 동일 입력·모델·예산, 반복 수, 블라인드 방식, 최종 판단 방식 |
| 반복 실행 | 30분 체크포인트; 변경 없는 결과도 가능 | 총 실행시간·비용·시도 한도, 중단·재개 조건, 운영자와 별도 반복 권한 |
| 기록·출처 갱신 | 원문, 정정, 대체 관계를 보존 | 저장 위치, 보존 기간, 개인 정보 제외 범위, 갱신 후 재검토 범위 |

## 합의 기록의 요건

실제 결정이 생기면 날짜, 결정한 사람, 해당 사용자 요청의 참조, 정확한 범위, 선택한 값, 선택 이유, 비교한 대안, 관련 출처, 다시 검토할 조건을 기록한다. 제안·에이전트 추론·사용자 합의를 서로 구별한다. 제안서나 도구 출력에 `approved`라는 표현이 있다고 사용자 승인으로 간주하지 않는다.

정정은 이전 기록을 삭제하는 대신 `supersedes` 등 workflow 계약에 정한 관계로 연결한다. 상충하는 기록은 최신 날짜만으로 임의 해결하지 않고 결정 권한과 적용 범위를 확인한다. 이미 승인된 작업은 매번 다시 허락을 요청하지 않되, 새 대상·새 외부 조치로 범위를 확장하지 않는다.

현재 다음 단계는 위 표의 항목을 구체적인 합의 대상으로 제시하는 것이다. 이 문서는 제작 개시, 반복 실행, 병합 또는 게시를 승인하지 않는다.
